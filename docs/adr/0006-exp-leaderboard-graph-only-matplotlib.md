# ADR-0006 — 경험치 리더보드 표 폐기·matplotlib 레벨 추이 그래프 단일화

- **상태:** 채택 (Accepted)
- **일자:** 2026-06-15
- **관련 문서:** [leaderboard-ui-improvements-work-order.md](../leaderboard-ui-improvements-work-order.md)(1차 작업지시서 — 본 ADR이 표시층을 대체), [ADR-0005](0005-exp-leaderboard-data-source.md)(데이터 소스 — 유지), [CONTEXT.md](../../CONTEXT.md)(경험치 리더보드·레벨 추이 용어)
- **이력:** 경험치 리더보드([#16](https://github.com/mindongdong/maple-mate/pull/16)·[#19](https://github.com/mindongdong/maple-mate/pull/19)) 출시 후 사용자 피드백 2라운드. 1차(작업지시서)는 표 다듬기 + 그래프 정규화 %p였으나, 2차 대화(2026-06-15)에서 표 폐기·그래프 단독화·matplotlib·절대 레벨 축으로 피벗. PR #21.

## 맥락 (Context)

리더보드는 출시 시 **순위표 PNG**(순위·닉·레벨(exp%)·어제 Δ·전체 서버 순위) + **7일 일일 Δ 라인 그래프**(PIL 직접 그리기)를 한 메시지에 함께 보냈다. 출시 후 피드백:

1. 표의 전체 순위·"어제 획득" 컬럼이 군더더기 → 1차에서 4컬럼으로 정리(작업지시서 F1·F2).
2. 그래프 y축(절대 Δ 경험치 억/조)이 비직관적·이상치 1개가 축 지배 → 1차에서 7일 전 대비 진행량(%p) 정규화로 교체(F3).
3. 2차 피드백: **표와 그래프를 굳이 함께 볼 필요가 없고**, 그래프가 여전히 **정보가 부실**하다. "각 점에 캐릭터 레벨(%)을 표기하면 비교가 편하지 않나? 그래프 라이브러리로 더 예쁘고 직관적으로."

그래프는 코드베이스 최초의 선그래프를 **PIL `ImageDraw`로 직접** 그리고 있었다(축·격자·범례·라벨 전부 수작업) → 점 라벨·면적·예쁜 눈금 추가가 비싸고 폴리시 한계가 뚜렷했다.

## 결정 (Decision)

**표를 폐기하고, `/경험치`·매일 10시 발송을 matplotlib로 그린 "최근 7일 레벨 추이" 그래프 PNG 1장으로 단일화한다.**

1. **표 폐기.** `LeaderboardPayload`는 그래프 1장(`graph_png`)만, 임베드 메인 이미지 = 그래프. 순위표 렌더(`render_table`)·라벨 헬퍼(`_level_text`·`_delta_text`)·전체 순위 표기를 제거. 등재 2명 게이트(`MIN_RANKED`)는 `build_rows`(누적 정렬·미등재 제외)의 등재 카운트로 유지(렌더는 안 하되 게이트 단일 출처).
2. **렌더는 matplotlib.** PIL 직접 그리기를 폐기하고 `render_progress_graph`를 matplotlib **OO API**(`Figure` + `FigureCanvasAgg`, `pyplot` 전역상태 미사용 → `asyncio.to_thread` 워커스레드에서 동시 렌더 안전)로 재작성. 다크 팔레트·한글 폰트 후보(`_FONT_CANDIDATES`)는 `table_image`와 공유.
3. **Y축 = 절대 연속 레벨.** `progress = character_level + exp_rate/100`(예: Lv.287 69% → 287.69)을 정규화 없이 그대로 그린다. **각 점에 `Lv.287 (69%)` 라벨**, 범례에 **유저별 일평균 %/일**(= (끝−처음 가용 레벨)×100 ÷ 사이 일수). 레벨업 마커 없음(연속값). 데이터 0개 유저 제외, `None` 구간 선 끊김.
4. **어제 Δ(절대 획득량, 억) 표시 제외.** 데이터층은 그대로(`history_progress`는 진행도, `build_rows`는 게이트용 Δ를 계속 계산) 두되, 발송 산출물에서 절대 획득량 숫자는 빼고 그래프는 레벨 진행 전용으로 한다.

## 검토한 대안 (Alternatives Considered)

- **PIL 유지 + 보강** — *기각.* 새 의존성은 0이나, 점 라벨·면적 채움·예쁜 눈금·범례를 전부 수작업해야 하고 안티앨리어싱·자동 눈금 등 폴리시 한계가 분명. "더 예쁘고 직관적" 목표에 비용 대비 부적합.
- **plotly / pygal** — *기각.* 정적 PNG 발송용인데 plotly는 kaleido(헤드리스 크로미움급), pygal은 cairosvg 같은 무거운 변환 의존성을 들여야 한다. Discord 정적 이미지엔 과함.
- **정규화 %p 부채꼴 축 유지(1차 F3)** — *기각(트레이드오프 인지 하).* 전원 0 출발이라 레벨 무관 공정 비교가 강점이나, 사용자가 점마다 **절대 레벨 라벨**을 원했고 절대 축이 라벨과 일치해 더 직관적이라 판단. 대가로 아래 "레벨차 민감성"을 받아들인다.
- **표 유지(보완 렌즈)** — *기각.* 표=구체 획득량, 그래프=레벨 진행의 보완 관계였으나, 매일 발송에 표+그래프가 매번 붙는 부담 + 사용자의 단독화 선호로 그래프 1장이 더 가볍고 명확.

## 결과 (Consequences)

**긍정**
- 정보 밀도↑: 점마다 실제 레벨(exp%)이 보이고, 범례 일평균으로 성장 속도가 한눈에. 라인 모양으로 추세, 라벨로 절대치를 동시에 전달.
- 렌더 코드↓·미려↑: 축·눈금·범례·라벨을 라이브러리가 처리. 다크 테마·한글 폰트는 표와 공유해 톤 유지.
- 매일 발송이 그래프 1장으로 가벼워짐.

**부담 / 잔류**
- **의존성 추가:** `matplotlib`(+numpy, ~수십 MB). 서버사이드 이미지 렌더 봇이라 정당. **Render 컨테이너에 한글 폰트(`fonts-nanum`) 필요** — 미설치 시 그래프 한글이 tofu(□)로 깨지며 import 시 경고 로그를 남긴다(표 렌더 `table_image`도 동일 폰트라 기존 배포에 있으면 무손상).
- **절대 레벨 축의 레벨차 민감성:** 레벨이 크게 다른 캐릭(예: 신규 저렙 150 vs 메인 287)이 끼면 Y축이 넓게 벌어져 **전원 라인이 납작해지고 기울기 비교가 약화**된다(정규화 %p였다면 회피했을 부분). 친구 그룹은 전원 고렙이라 실관측 드물어 **그대로 두기로 결정(2026-06-15)**. 빈번해지면 옵션: 정규화 %p 회귀 / 레벨차 큰 캐릭 분리·제외.
- **7일 미만 신규 캐릭:** 종합 랭킹 등재 이전 날짜는 스냅샷이 없어 **첫 등장일부터의 부분 라인**으로 그려진다(이전 구간 빈칸). 길드당 백필은 1회뿐이라 기존 길드의 새 멤버는 등록 후 하루 1점씩 누적. 가용 점이 1개뿐이면 범례가 `평균 0.0%/일`로 표기(성장 0이 아니라 "측정 2점 부족"인데 0으로 보이는 경미한 오해 — 허용).
- **ADR-0005 표시층 대체:** 데이터 소스 결정(`ranking/overall` 단일 + `exp%` best-effort)은 **유지**된다. 다만 0005 결과에 적힌 표시 항목(순위표·어제 Δ 병기·전체 서버 순위 표기)은 본 ADR로 **표시층에서 폐기**된다 — `world_rank`·`total_exp`·Δ는 스냅샷에 계속 적재되지만 그래프엔 노출하지 않는다.
- **마이그레이션 없음**(`exp_rate`·`character_level` 컬럼 기존재). 검증: ruff clean + `pytest -m 'not live'` 503 통과, 별도 code-reviewer APPROVE(CRITICAL/HIGH 0), 실데이터 미리보기 PNG 눈 확인.
