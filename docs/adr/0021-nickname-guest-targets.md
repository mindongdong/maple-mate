# ADR-0021 — 비교 대상 닉네임 직접 지정 (게스트 대상)

- **상태:** 채택 (Accepted)
- **일자:** 2026-10-12
- **관련 문서:** [target-unification-work-order.md](../target-unification-work-order.md)(빌드 단위·테스트), [ADR-0008](0008-unspecified-comparison-fanout-cap.md)(무인자 팬아웃 — 같은 날 `/스펙` K=5 개정), [ADR-0006](0006-multi-character-data-model.md)(멀티 캐릭터·대표), [comparison.py](../../maple_mate/bot/comparison.py)(`parse_nicknames`·`resolve_mixed_targets`), [registration/service.py](../../maple_mate/registration/service.py)(`find_guild_characters_by_nicknames`·`resolve_guest_target`·`is_guest`)

## 맥락 (Context)

`/스펙`·`/아이템`·`/유니온`은 비교 대상을 **디스코드 멤버**로만 받았다. 멤버마다 대표 캐릭터 1명이
대상이 됐다. 그래서 두 가지를 할 수 없었다:

- 서버에 등록하지 않은 캐릭터(길드원·라이벌·지인)와의 비교
- 친구의 **대표가 아닌 캐릭터**(부캐) 지정

세 명령은 앱 키 + ocid만 있으면 조회되는 공개 데이터다. 따라서 등록 여부는 조회 자체의 제약이
아니다. 등록은 "누구의 캐릭터인지(태그)"와 대표 해석에만 필요하다.

## 결정 (Decision)

1. **`닉네임` 파라미터 1개(쉼표 구분)** 를 세 명령에 추가한다. 유저 슬롯과 합쳐 **최대 5명**이다.
   초과는 **명령 체크**(`target_limit_check`)로 조회 전에 ephemeral 거부한다. 체크를 쿨다운보다
   먼저 실행해 거부가 쿨다운을 소모하지 않게 한다(입력을 고쳐 바로 재실행 가능). 파싱은 공백 제거·
   빈 토큰 무시·대소문자 무시 중복 제거다.
2. **해석 순서 = 등록 캐릭터 우선.**
   - 이 서버 등록 캐릭터와 닉(대소문자 무시)이 일치하면 그 캐릭터를 쓴다. 대표 여부·realm은
     따지지 않는다. 넥슨 0콜이고 소유자 태그가 붙는다.
   - 미일치만 `/id` 1콜로 **게스트 대상**을 만든다.
   - 둘 다 실패하면 부분성공 행 "캐릭터를 찾을 수 없어요"를 낸다.
   - 닉 지정은 명시적 의도라 realm 필터를 적용하지 않는다(유저 슬롯 경로의 realm 필터는 그대로).
3. **게스트 = `discord_user_id 0`인 `Target`, 비저장.**
   - `Target`에 필드를 추가하지 않는다. 판별은 `is_guest()`다. 0은 스노우플레이크에 없어
     충돌하지 않는다.
   - 범례는 닉네임만 나오고 태그는 없다(`mention()` 기존 동작). 별도 마커는 넣지 않는다.
   - `_fetch_one`의 스테일 ocid 분기는 게스트면 닉 재조회·DB 갱신 없이 "찾을 수 없어요"로 끝낸다.
   - error_log는 `discord_user_id=None`으로 적재한다. 게스트 `/id` 해석의 가용성 오류(장애·rate
     limit 등)도 같은 기준으로 적재한다(닉 없음은 운영 대응 대상이 아니라 미적재).
4. **순서·중복**: 유저(입력순) → 닉네임(입력순)으로 쌓는다. 같은 ocid는 첫 번째만 남긴다.
   표시 정렬은 명령별 기존 규칙(ADR-0008 개정 2)을 따른다.
5. **무인자 판정 = 유저 슬롯·닉네임 모두 비었을 때.** 닉네임이 없으면 기존 `resolve_targets`
   경로를 그대로 탄다(회귀 0).

## 검토한 대안 (Alternatives Considered)

- **닉네임1~5 별도 슬롯** — 입력은 명확하지만 옵션 목록이 길어진다(유저 5 + 닉 5). 쉼표 1칸으로
  충분하다. 기각.
- **게스트 캐릭터 DB 저장(캐시)** — 등록 모델과 섞여 "등록자" 의미가 흐려지고 정리 정책이 필요하다.
  `/id` 1콜은 싸다. 기각.
- **항상 `/id`로 해석(등록 캐릭 우선 없음)** — 등록된 친구 부캐에도 태그가 안 붙고 호출만 는다. 기각.
- **`/경험치`·`/스타포스`·`/잠재` 확장** — 경험치는 등록자 DB 스냅샷 기반이고, 이력류는 개인 키 계정
  합산이라 미등록 캐릭터에 의미가 없다. 스코프 아웃.

## 결과 (Consequences)

- 미등록 캐릭터와 친구 부캐를 슬래시 한 번으로 비교할 수 있다. 사이트 유니온 tip의 "닉네임 조회"
  서술이 사실이 됐다.
- 게스트 1명당 넥슨 `/id` 1콜이 추가된다(등록 캐릭 일치 시 0). 상한 5라 최악 +5콜이다.
- 같은 닉이 서버에 여러 명 등록돼 있으면 (유저, ocid) 오름차순 첫 행이 잡힌다(드문 경우 — 유저
  슬롯으로 지정하면 회피 가능).
- PR2(탭 전환)는 이 해석 결과(게스트 포함 Target 목록)를 그대로 재사용한다.
