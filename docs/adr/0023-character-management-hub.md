# ADR-0023 — `/캐릭터목록` 관리 허브: 캐릭터 삭제 · 대표 자동 복귀 · 개인 키 삭제

- **상태:** 채택 (Accepted)
- **일자:** 2026-10-14
- **관련 문서:** [character-manage-hub-work-order.md](../character-manage-hub-work-order.md), [ADR-0006](0006-multi-character-data-model.md)(멀티 캐릭터·대표), [ADR-0001](0001-nexon-personal-key-model.md)(개인 키), [ADR-0012](0012-scheduler-reminder-per-user-dm.md)(스케줄러 구독), [ADR-0019](0019-user-install-dm-workspace.md)(DM 스코프), [registration/commands.py](../../maple_mate/registration/commands.py)·[registration/service.py](../../maple_mate/registration/service.py)

## 맥락 (Context)

등록은 추가·갱신만 가능했다. 캐릭터 삭제·키 삭제·대표 수동 지정 해제 수단이 봇에 없어서 다음 문제가 있었다.

- 유저당 캐릭터 상한(10)에 걸리면 안 쓰는 캐릭터를 비울 수 없었다.
- 민감 정보인 개인 키를 본인이 지울 수 없었다(다른 키로 덮어쓰기만 가능).
- 대표를 한 번 수동 지정하면 자동(최고 레벨)으로 돌아갈 수 없었다.

## 결정 (Decision)

1. **진입점 = 기존 `/캐릭터목록`을 관리 허브로 확장.** 새 명령은 없다. 결과(ephemeral) 아래 버튼
   `🗑️ 캐릭터 삭제`·`👑 대표 변경`·`🔑 키 삭제`를 둔다. 상태마다 컴포넌트를 다시 그려 같은 메시지를 교체한다.
   캐릭터도 키도 없으면 기존 안내만 보낸다(관리할 것이 없음).
2. **파괴적 작업은 확인 단계를 거친다.** 삭제(여러 개 선택 → `N개 삭제` 확인)와 키 삭제(확인)는 한 번 더
   눌러야 실행된다. 대표 변경은 되돌릴 수 있어 바로 적용한다.
3. **캐릭터 삭제 범위.** `character` 행만 지운다. 지운 캐릭터가 대표 포인터였으면 NULL(자동)로 되돌린다.
   **경험치 스냅샷은 남긴다** — 리더보드·`/내캐릭터`는 현재 등록 캐릭터만 보고, 90일 prune이 정리하며, 재등록 시
   추이가 이어진다. 본인 것이 아닌 ocid는 무시한다.
4. **대표 변경에 '자동' 선택지.** Select 첫 항목 `자동 (등록 캐릭터 중 최고 레벨)` = `representative_ocid` NULL.
5. **키 삭제는 스케줄러알림 구독을 함께 해제한다.** 남기면 매시 잡이 키 없음으로 조용히 건너뛰기만 해 유저가
   알림이 끊긴 이유를 모른다. 캐릭터는 유지한다(스펙류는 키 없이 조회된다). 한 트랜잭션에서 처리한다.
6. **스코프는 기존 그대로**(길드 = guild_id, 봇 DM = 워크스페이스 0). 서버별 데이터는 서로 영향이 없다.
7. **View 수명.** 유휴 300초 후 컴포넌트를 제거한다. 마지막 클릭 토큰으로 지운다(ADR-0022와 같은 이유).

## 검토한 대안 (Alternatives Considered)

- **별도 명령(`/캐릭터삭제`·`/키삭제`)** — 명령 목록이 늘고 사이트 문서도 늘어난다. 사용자가 허브 확장을 선택. 기각.
- **삭제 시 경험치 스냅샷도 삭제** — 재등록 시 추이가 끊기고, 90일 자동 정리로 충분하다. 기각.
- **전체 등록 해제(탈퇴) 버튼** — 이번 범위에서 제외(사용자 결정). 필요하면 같은 허브에 추가한다.

## 결과 (Consequences)

- 상한에 걸린 유저가 스스로 정리할 수 있고, 개인 키를 본인이 지울 수 있다.
- 명령 이름이 바뀌지 않아 사이트 드리프트 가드는 그대로다(카피만 갱신).
- PR3b(키 기반 계정 동기화)는 같은 허브에 `🔄 계정 동기화` 버튼을 추가하는 방식으로 이어진다.
