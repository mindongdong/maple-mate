# ADR-0007 — 이력류(`/스타포스`·`/잠재`) 계정 전체 합산: 등록 닉 필터 제거

- **상태:** 채택 (Accepted) — CONTEXT.md "이력류 스코프 vs 집계 단위" Phase 3 결정을 **대체(supersedes)**
- **일자:** 2026-06-15
- **관련 문서:** [n-characters-work-order.md](../n-characters-work-order.md)(결정 10·12·Phase 4), [n-characters-as-built.md](../n-characters-as-built.md)(as-built), [CONTEXT.md](../../CONTEXT.md)(이력류·부재 상태), [ADR-0006](0006-multi-character-data-model.md)(데이터 모델), [ADR-0002](0002-starforce-luck-metric.md)(운빨 지표)
- **이력:** 멀티 캐릭터 등록 그릴링(2026-06-15) 결정 10·12. PR #22.

## 맥락 (Context)

넥슨 history API(`history/starforce`·`history/cube`·`history/potential`)는 **개인 키 = 계정** 스코프라 그 계정의 **전체 캐릭터** 이력을 반환한다(`character_name` 이 캐릭터별로 상이). 기존(Phase 3, ADR-0001 시기) 코드는 `parse_attempts(records, nickname)`로 **등록 닉네임과 일치하는 캐릭터만 필터**해 등록 캐릭터 1개 단위로 집계했다 — CONTEXT.md "이력류 스코프(계정) vs 집계 단위(캐릭터)"에 명시된 결정이었고, 부캐 강화는 집계에서 빠졌다(MVP).

멀티 캐릭터화로 이 전제가 무너졌다. 유저가 N개 캐릭터를 등록하는데 등록 닉 1개로 필터하면 **임의의 한 캐릭터만** 집계된다. 작업지시서의 사용자 추측("개인 키 기반 기능은 계정 전체 데이터")은 **정확했고**, 현재 코드가 굳이 되돌려 필터하고 있던 것이다([history/service.py](../../maple_mate/history/service.py)).

## 결정 (Decision)

**`/스타포스`·`/잠재` 집계 단위를 등록 캐릭터 1개에서 계정 전체 합산으로 바꾼다.**

1. **닉 필터 제거** — `parse_attempts`·`parse_cube_records`·`parse_reset_records`는 닉 인자 없이 계정 전체를 반환하되 `character_name`을 보존한다.
2. **그룹 키 = `(character_name, target_item)`** — `aggregate_starforce`가 동명 장비를 캐릭터별로 분리한다. 서로 다른 캐릭터의 같은 이름 장비가 한 묶음으로 합쳐져 시작★→최종★이 과대 계산되는 **병합 버그를 차단**한다.
3. **표시 = 합산 통합값**(결정 12) — 비교표 "대상" 컬럼은 **대표 닉**으로 라벨하고, "계정 전체 합산(부캐 포함)" 안내 필드를 단다. 캐릭터별 N행 분리는 하지 않는다.
4. **캐시 앵커 = `min(created_at)` 캐릭터 ocid** — 계정 전체 데이터를 유저당 1개 안정 키로 캐싱한다(닉/대표 변경에도 흔들리지 않음).
5. **`/비틱`은 예외 — 대표 기준 유지**(결정 12). 계정 전체 결과를 대표 닉으로 필터하고 아이콘·장착레벨은 대표 ocid로 잡는다(앵커 ocid와 분리).

## 검토한 대안 (Alternatives Considered)

- **대표 1캐릭터만 집계(스펙류와 동일 단위 유지)** — *기각.* 키가 계정 전체를 주는데 대표 1개만 집계하면 부캐 강화가 통째로 사라진다. 사용자 기대("내 계정의 운빨")와 불일치하고, 키 1개로 전 캐릭터를 볼 수 있다는 개인 키 모델(ADR-0001)의 이점을 버린다.
- **캐릭터별 분리 표시(유저당 N행)** — *기각.* 다인 비교표가 캐릭터 수만큼 폭발한다. 비교의 목적은 "누가 운 좋았나"라 계정 합산 1행이면 충분(결정 12). 단일 대상 보조 분해는 백로그.
- **`/비틱`도 계정 전체화** — *기각.* `/비틱`은 "이 장비 이렇게 운 좋게 띄웠다" 자랑 카드라 **특정 캐릭터의 특정 장비**가 단위다. 계정 전체로 풀면 부캐 장비가 대표 자랑에 섞인다(결정 12 — 대표 기준 유지).

## 결과 (Consequences)

**긍정**
- 개인 키 1개로 **계정 전체 운빨**(스타포스·잠재)이 합산된다 — 부캐 강화도 반영. 사용자 추측대로의 직관적 동작.
- `(character_name, target_item)` 그룹핑이 동명 장비 병합 버그를 구조적으로 막는다(멀티 캐릭터에서 같은 이름 장비가 흔함).
- 캐시 앵커가 닉/대표 변경과 무관해 같은 키의 콜드 재페치를 최소화(ADR-0004 스로틀 보호와 정합).

**부담 / 잔류**
- **합산 운지수에 서로 다른 월드·레벨 캐릭터가 혼합**된다(결정 10·12 수용) — "계정 전체"라는 단위 자체의 성질.
- **닉 변경 시 과거 이력의 `character_name` 불일치** 잔류 — 그 캐릭터 과거 기록이 다른 이름으로 잡힐 수 있음(캐시 앵커는 ocid 기반이라 무관). 경험치 리더보드는 `ranking/overall?ocid=`라 이 리스크 없음(ADR-0005).
- **`/비틱` 대표 닉 ≠ 레코드 `character_name`(닉변경)** 이면 자랑할 항목이 빈 결과가 될 수 있음 — 대표 닉을 현행화하면 해소(엣지).
