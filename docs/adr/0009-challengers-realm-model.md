# ADR-0009 — 챌린저스 realm 모델: `world_name` 접두 판정 + 명령별 모드 파라미터 + 이력류 분리 비대칭

- **상태:** 채택 (Accepted) — ⚠️ [ADR-0015](0015-history-account-identity-display.md)가 **`/스타포스`·`/잠재`에 한해 결정 2(모드 파라미터)·4(이력류 realm 분리)를 되돌림**(계정 전체=본+챌 합산, realm 무관). ⚠️ [ADR-0017](0017-notification-unification-and-dm-subscription.md)가 **`/스케줄러`·스케줄러 알림에 한해 모드·realm 구독 분리를 되돌림**(등록 캐릭터 전부, 뱃지는 캐릭터 world로 per-character 파생). 나머지 명령(`/스펙`·`/아이템`·`/경험치`)과 리더보드 realm 분리는 유효.
- **일자:** 2026-06-19
- **관련 문서:** [challengers-mode-work-order.md](../challengers-mode-work-order.md)(그릴링 10결정·빌드 6단계·realm 처리표), [CONTEXT.md](../../CONTEXT.md)(realm·모드 용어), [ADR-0005](0005-exp-leaderboard-data-source.md)(경험치 소스 = `ranking/overall`), [ADR-0006](0006-multi-character-data-model.md)(멀티 캐릭터·대표 포인터·**exp_snapshot PK 불변** — 본 ADR이 일부 되돌림), [ADR-0007](0007-history-account-wide.md)(이력류 계정 전체화)
- **이력:** 챌린저스 서버 모드 그릴링(2026-06-19) 결정 1~10. PR #(채번 예정). fanout ADR-0008 이 미머지 브랜치를 점유해 0009 채번.

## 맥락 (Context)

여름 이벤트로 **챌린저스 서버**(시즌 한정, 6/18 신설)가 열렸다. 유저는 본서버 캐릭터와 챌린저스
캐릭터를 동시에 등록해 두고, 캐릭터 관련 명령마다 어느 서버를 볼지 고른다. 핵심 요구는 **본서버
캐릭터와 챌린저스 캐릭터가 절대 같이 비교되지 않는 것**(누수 0)이다.

라이브 프로브(닉 `힘찬하악질`·`제주도정민규`·`중망레테`, 전부 `챌린저스3`·Lv.260)로 확정한 사실:

- 챌린저스 캐릭터는 **기존 `id`→`character/*` 흐름 그대로** 조회된다. 별도 API 네임스페이스 없음.
  realm 신호는 응답 `world_name` 의 `챌린저스` 접두뿐이다.
- `ranking/overall` 은 챌린저스에 대해 **200 + 빈 배열**(에러 아님). 6/18 신설이라 누적 랭킹 미생성 —
  도메인의 **"랭킹 미등재"(Not ranked)** 상태로 자연 흡수된다(ADR-0005). 넥슨이 생성하면 자동 작동.
- `history/starforce` 레코드엔 **`world_name` 이 있으나**(`docs/api/history.md:324·422`),
  `history/cube`·`history/potential` 레코드엔 **없다**. → 이력류 realm 분리 신호가 명령별로 다르다.
- `user/union` 은 챌린저스에 대해 전부 null → `/유니온` 본서버 전용 유지 근거.

## 결정 (Decision)

### 1. realm 판정 = `Character.world` 스냅샷 + 순수 술어

등록 시 `character/basic` 의 `world_name` 을 `Character.world`(nullable) 에 스냅샷한다.
판정은 순수 술어 `is_challengers(world) = bool(world) and world.startswith("챌린저스")`
([registration/realm.py](../../maple_mate/registration/realm.py)). **NULL = 본서버**(레거시 —
챌린저스가 6/18 신설이라 마이그레이션 시점 행은 전부 본서버). `챌린저스N` 은 전부 한 realm.
백필 없음, lazy 갱신은 재등록 편승.

### 2. 모드 = 명령별 무상태 `모드` 파라미터 (본서버 기본 / 챌린저스)

6개 명령(`/스펙`·`/아이템`·`/스타포스`·`/잠재`·`/비틱`·`/경험치`)에 `모드` 파라미터를 단다
([bot/modes.py](../../maple_mate/bot/modes.py), choice value = `Realm.value`).
> ⚠️ **개정([ADR-0015](0015-history-account-identity-display.md)):** `/스타포스`·`/잠재`는 계정 전체(본+챌 합산)로 정렬되며 **모드 파라미터를 제거**했다 — 현재 모드 명령은 4개(`/스펙`·`/아이템`·`/비틱`·`/경험치`). 공개 게시 봇에서
숨은 토글 사고를 피하려 **무상태**(미지정=본서버). 쿨다운은 `(유저, 명령)` 공유(모드 미반영).
`/유니온` 은 **모드 미부착·코드 무변경**(본서버 전용 — 챌린저스 union 은 어차피 null).

### 3. 대표 = 단일 포인터 + realm 인지 해석

`pick_representative(characters, representative_ocid, realm)` 가 realm 후보만으로 대표를 해석한다
(스키마 무변경). 수동 핀은 가리키는 캐릭터가 그 realm 에 있을 때만 효력, 반대 realm 핀은 무시되고
그 realm 내 자동 대표(최고 레벨)가 된다. `get_targets(realm)` 은 그 realm 캐릭터 미보유 유저를
대상에서 제외한다(본서버 비교에 챌린저스 누수 0).

### 4. 이력류 분리 비대칭 (이 ADR의 핵심)

이력류는 명령마다 realm 신호가 달라 **분리 수단이 비대칭**이다:

| 명령 | realm 거름 수단 | 근거 |
|---|---|---|
| `/스타포스` | **레코드 `world_name`** 정밀 필터 | 레코드에 `world_name` 존재 → 미등록 챌린저스 부캐 강화도 정확히 분리 |
| `/잠재` | **등록 `{닉네임→realm}` 맵** 필터 | cube/potential 레코드에 `world_name` **부재** → 등록 닉맵으로 추정, 미상 닉→본서버 |
| `/비틱` | **챌린저스 대표 닉** 교체 | 대표 기준 유지(ADR-0007 결정 12) — 챌린저스 모드면 챌린저스 대표로 닉 필터·ocid 아이콘 |

> ⚠️ **개정([ADR-0015](0015-history-account-identity-display.md)):** `/스타포스`·`/잠재` 행은 더 이상 유효하지 않다 — 두 명령은 realm 무관(본+챌 합산)으로 바뀌어 위 표는 **`/비틱` 한 줄만 유효**(대표 닉 기준 유지). 아래 "미등록 챌린저스 부캐의 잠재 공백" 한계도 `/잠재` realm 분리가 사라지며 해소(대신 챌린저스 잠재가 본서버와 합산됨).

수용된 한계: **미등록 챌린저스 부캐의 잠재 공백** — cube/potential 에 `world_name` 이 없어 등록 안
한 챌린저스 부캐의 잠재는 본서버로 떨어질 수 있다. `/스타포스` 는 `world_name` 으로 정확하고,
실전(챌린저스 캐릭터를 등록함)에선 무영향이라 수용한다.

### 5. 경험치 리더보드 = realm별 2개 완전 분리 (`exp_snapshot` PK 확장)

길드당 본서버·챌린저스 리더보드를 완전 분리한다(각 독립 `MIN_RANKED` 게이트, `/경험치알림`
단일 토글이 양쪽 제어). **dual-realm 유저는 같은 날 두 realm 대표 스냅샷이 공존**해야 하므로
`exp_snapshot` PK 를 `(guild, user, date)` → `(guild, user, date, realm)` 로 확장한다.

> **이것은 ADR-0006 "exp_snapshot PK (guild,user,date) 불변" 을 의도적으로 되돌리는 결정이다.**
> ADR-0006 의 PK 불변은 멀티 캐릭터(유저당 대표 1명) 맥락의 전제였다. 챌린저스로 유저가 realm당
> 대표 1명씩 = 최대 2명을 가지게 되어, 같은 키에 두 스냅샷을 담아야 누수 없이 두 리더보드를
> 만들 수 있다. 코드 레벨 필터만으로는(realm 컬럼 없이) dual-realm 유저의 스냅샷이 충돌해 한쪽
> 리더보드에서 누락되거나 다른 realm exp 가 새는 잠재 버그가 남는다(넥슨이 챌린저스 랭킹을
> 생성하는 순간 발현). realm 디스크리미넌트를 PK 에 넣는 것이 유일하게 누수 0 + 미래 안전하다.

적재(`fetch_and_store`)는 realm 무관 전원(본서버+챌린저스 대상 union) — 각 대상이 대표 world 에서
파생한 realm 으로 저장된다. 미등재는 스킵(현재 챌린저스는 빈 랭킹 → 챌린저스 스냅샷 0 → 챌린저스
리더보드 빈 상태, 에러 아님).

### 6. 라벨 = `🏆 챌린저스` 프리픽스, 본서버 무라벨

챌린저스 모드 출력 제목에 `🏆 챌린저스` 를 붙인다(`/캐릭터목록` realm 표기, `/비틱` 카드,
리더보드 제목 `📈 경험치 리더보드` vs `🏆 챌린저스 경험치 리더보드`). 본서버 출력은 **시각적
회귀 0**(무라벨·기존 문구 그대로).

## 검토한 대안 (Alternatives Considered)

- **별도 `challenger_*` 테이블/네임스페이스** — *기각.* API가 같은 흐름이고 신호가 `world_name`
  뿐이라 테이블 분리는 과잉. 적재는 realm 무관이고 분리는 "대상 집합·발송 빌드" 단계에서만 필요.
- **상태 저장 모드 토글(채널·유저 단위)** — *기각.* 공개 봇에서 숨은 상태는 오발송 사고를 낳는다.
  명령별 무상태 파라미터가 기존 무상태 철학과 정합.
- **exp_snapshot 스키마 무변경 + 코드 레벨 realm 필터** — *기각.* dual-realm 유저의 (guild,user,date)
  스냅샷이 한 행뿐이라 두 realm 대표를 담을 수 없다. 챌린저스 랭킹 생성 시 누락/누수 잠재 버그.
  realm 을 PK 에 넣어야 결정 8(2개 완전 분리)과 누수 불변식을 진짜로 만족한다(사용자 승인).
- **`/잠재` 도 `world_name` 정밀 분리** — *불가.* cube/potential 레코드에 `world_name` 이 없다.
  등록 닉맵이 차선이며, 미등록 부캐 공백은 수용(결정 4).

## 결과 (Consequences)

**긍정**
- realm 신호가 `world_name` 한 곳이라 판정이 순수 술어 한 줄. 적재는 realm 무관이라 단순.
- 본서버 비교·리더보드에 챌린저스가 일절 안 섞인다(누수 0 불변식). 챌린저스 빈 랭킹은 "랭킹
  미등재"로 자연 흡수 — 넥슨이 생성하면 자동 작동.
- 본서버 출력 시각적 회귀 0(챌린저스만 라벨·realm 표기).

**부담 / 잔류**
- **이력류 분리 비대칭** 자체가 인지 비용 — `/스타포스`=world_name·`/잠재`=닉맵·`/비틱`=대표.
- **미등록 챌린저스 부캐의 잠재 공백**(결정 4) · **닉 변경 시 `/잠재` 닉맵 스테일**(기존 이력류 한계).
- **두 realm 동시 수동 핀 불가** — 단일 포인터라 챌린저스 핀이 본서버 핀을 덮는다. 챌린저스 부캐
  ≈1개라 실수요 낮음(필요 시 포인터 2개로 확장).
- **`exp_snapshot` PK 확장**으로 ADR-0006 의 PK 불변 동결을 되돌림 — 다운그레이드는 챌린저스 행
  삭제로 유일성 복원(손실 허용).
- **모드 파라미터 전역 노출** — Discord 슬래시 파라미터는 유저별 숨김 불가라 챌린저스 미보유
  유저에게도 보인다. 런타임 안내(미보유 시 '챌린저스 캐릭터 미등록')로 처리.
