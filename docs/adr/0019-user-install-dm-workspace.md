# ADR-0019 — 유저 설치(User Install) 지원: 센티널 guild_id=0 "DM 워크스페이스"

- **상태:** 채택 (Accepted)
- **일자:** 2026-07-03
- **관련 문서:** [user-install-work-order.md](../user-install-work-order.md)(빌드 단위·G0 게이트), [ADR-0006](0006-multi-character-data-model.md)(멀티 캐릭터 (guild_id, user_id) 키 — 본 ADR이 그 키 공간에 가상 스코프 1개를 추가), [ADR-0017](0017-notification-unification-and-dm-subscription.md)(개인 DM 구독 — 발송 경로 재사용), [ADR-0018](0018-my-character-solo-comparison.md)(솔로 유저 가치 — 본 ADR의 주 수혜 명령)
- **이력:** `/grill-me` 그릴링(2026-07-03) — 결정 6건 확정.

## 맥락 (Context)

봇은 현재 **서버(길드) 설치 전용**이다. 개인 유저가 쓰려면 봇이 있는 서버에 들어가야 하고, 서버를 만들 관리 권한이 없으면 진입 자체가 막힌다. Discord의 유저 설치 앱(User-Installed Apps, 2024-03 GA)은 봇을 **개인 계정에 설치**해 봇 DM에서 슬래시 커맨드를 쓰게 해주므로, 서버 미소속 개인 유저에게 진입로를 열 수 있다.

제약 세 가지:
1. **모든 데이터가 길드 키다** — Registration PK `(guild_id, discord_user_id)`, Character PK `(guild_id, discord_user_id, ocid)`. 글로벌 유저 테이블이 없고, 모든 서비스 함수가 이 키로 조회한다. 유저 설치 DM 인터랙션에는 `guild_id`가 없다.
2. **유저 설치 ≠ DM 전용** — `allowed_contexts`에 따라 그룹 DM, 심지어 **봇 미초대 서버**에서도 호출될 수 있고, 그 경우 `interaction.guild_id`가 존재해 길드 키잉이 오작동할 수 있다. 또한 `allowed_contexts`는 설치 경로(길드/유저)별로 분리 지정이 안 된다.
3. **비교·리더보드 명령은 "서버 등록자 집합"이 전제** — DM에는 그 집합 자체가 없다.

## 결정 (Decision)

**DM 컨텍스트를 `guild_id=0`인 가상 스코프("DM 워크스페이스")로 취급하고, 본인 단위 명령만 유저 설치 경로(봇 DM 전용)에 개방한다. 스키마·서비스 함수 무변경.**

1. **1차 목표 유저 = 서버 미소속 개인 유저.** 등록→조회→알림 구독의 전 과정이 봇 DM에서 완결되어야 한다. 기존 서버 유저의 DM 편의는 비목표 — DM 등록은 서버 등록과 **별개 데이터**다(재등록 필요).

2. **데이터 키 = 센티널 `guild_id=0`.** Discord 스노우플레이크에 0이 없어 충돌 불가. 스키마 무변경·마이그레이션 0건, 모든 서비스 함수(`get_targets(0, ...)` 등)를 그대로 재사용한다. "유저가 서버 2곳이면 등록 2개"라는 기존 서버별 분리 철학과 일관 — DM은 세 번째 공간일 뿐이다.

3. **명령 분류.** 개방(유저 설치에서 보임) = 본인 단위 전부: `/가이드`, `/캐릭터등록`·`/키등록`·`/대표지정`·`/캐릭터목록`, `/내캐릭터`(스펙·아이템·경험치), `/스케줄러`, `/스케줄러알림`, `/공지알림`·`/썬데이알림`(**개인 DM 대상만** — 채널 대상은 거부 문구). 미개방 = 서버 개념이 전제인 것: `/스펙`·`/아이템`·`/유니온`·`/스타포스`·`/잠재`·`/경험치`(유저 간 비교·리더보드), **`/비틱`**(관객 없는 자랑은 무의미). 미개방 명령은 `allowed_installs(guilds=True)`만 지정해 유저 설치 목록에서 **아예 숨긴다**.

4. **컨텍스트 = 봇 DM 전용.** `allowed_contexts`가 설치 경로별 분리를 못 하므로(제약 2) 런타임 가드로 구현: `interaction.is_user_integration()`이고 길드 통합이 아니면서 `guild_id`가 있으면(= 봇 미초대 서버에서 유저 설치 호출) "봇 DM에서 사용해 주세요" 거부. 그룹 DM(`private_channels`)도 닫는다 — 개방 명령이 전부 본인 조회라 실익이 없다.

5. **알림·스케줄러 개방은 G0 스파이크가 게이트.** 크론 DM 발송(`send_dm`)이 "봇과 서버 미공유 + 유저 설치만" 상태의 유저에게 실제로 되는지 **구현 착수 전 실검증**한다. 실패 시 `/스케줄러알림`·`/공지알림`·`/썬데이알림`은 개방 목록에서 빼고 안내 문구로 대체한다(조회성 명령만 개방).

6. **패키징 = 본 ADR + 2 PR.** PR1 = 봇(센티널 스코프 헬퍼 + 데코레이터 + 런타임 가드 + 테스트), PR2 = 사이트·문서("내 계정에 추가" CTA·유저 설치 안내). 운영자 작업 = Developer Portal Installation Contexts에 User Install 활성화.

## 검토한 대안 (Alternatives Considered)

- **글로벌 계정 테이블 신설** — *기각.* 장기적 계정 통합의 기반은 되지만, 서비스층이 두 데이터 소스를 분기해야 하고 1차 목표(서버 미소속 유저 — 승계할 기존 데이터가 없음)에 과투자다(결정 2).
- **서버 등록 자동 승계(DM에서 기존 서버 데이터 재사용)** — *기각.* 어느 서버 것을 쓸지 규칙이 필요하고, 목표 유저에겐 승계할 데이터가 없다(결정 1·2).
- **타서버(봇 미초대) 호출 허용** — *기각.* 개인 응답이 공개 채널에 노출되고, 센티널 키잉이 실서버 guild_id와 충돌하는 예외 처리를 낳는다(결정 4).
- **미개방 명령을 보이되 거부 문구** — *기각.* `allowed_installs`로 숨기는 쪽이 멘탈 모델이 깔끔하다(결정 3).
- **/비틱 개방** — *기각.* 봇 DM에는 관객이 없다. 그룹 DM을 닫는 결정과 함께 자연 소멸(결정 3·4).

## 결과 (Consequences)

- 서버 없는 개인 유저도 계정 설치만으로 등록→`/내캐릭터`→숙제 DM 리마인더까지 쓸 수 있다 — ADR-0018 솔로 가치의 완성형.
- DM 등록과 서버 등록은 별개다: 같은 유저가 서버에서도 쓰려면 재등록(API 키 포함)해야 한다. 추후 계정 통합 시 guild 0 행이 자연스러운 시드가 된다.
- guild 0은 리더보드 채널·2인 게이트가 없는 스코프라 서버 전용 크론(경험치 방송 등)에서 자연히 배제된다 — 단, exp_snapshot 수집이 guild 0 등록 캐릭터를 포섭하는지는 구현 시 검증해야 한다(/내캐릭터 경험치의 데이터 원천).
- 유저 설치 유저 수만큼 넥슨 API 콜과 DM 발송이 늘지만, 전역 4req/s 스로틀과 키별 버킷(ADR-0004)이 기존대로 보호한다.
