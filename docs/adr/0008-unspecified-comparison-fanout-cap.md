# ADR-0008 — 무인자 비교 팬아웃 경계: K=10(본인 포함 랜덤) + 명령별 지표 정렬 + 이력류 키 미등록 숨김

- **상태:** 채택 (Accepted). 선정 규칙은 초안 **대표 레벨 상위** → **본인 포함 랜덤**으로 부분개정(아래 개정 노트).
- **일자:** 2026-07-04 (선정·정렬·푸터 개정 2026-07-04)
- **관련 문서:** [CONTEXT.md](../../CONTEXT.md)(대상·부분 성공 용어), [random-fanout-work-order.md](../random-fanout-work-order.md)(개정 빌드 단위·테스트·PR 분할), [ADR-0004](0004-per-key-throttle-buckets.md)(넥슨 키별 스로틀 — 팬아웃 속도의 물리적 하한), [ADR-0015](0015-history-account-identity-display.md)(이력류 표시 = 디스코드 유저·서버 이탈 제외), [comparison.py](../../maple_mate/bot/comparison.py)(`select_with_self`·`fanout_note`)
- **이력:** 2026-06 팬아웃 경계 그릴링에서 K=10·대표레벨 정렬이 결정됐으나 브랜치 미머지로 유실(ADR-0009 채번 각주에 흔적). 2026-07-04 라이브 QA 후 사용자 재확인으로 부활 — 이번엔 "무인자 키 미등록 숨김" 결정이 추가됐다. 같은 날 튜토리얼 검토 중 "대표 레벨 상위"가 상위권만 반복 노출돼 불공평하다는 사용자 판단으로 **본인 포함 랜덤**으로 부분개정하고, 명령별 지표 정렬·푸터 상시화를 함께 확정했다(그릴링 2026-07-04).

## 맥락 (Context)

`/아이템`·`/유니온`·`/스타포스`·`/잠재`는 대상을 지정하지 않으면 **서버 등록자 전원**(이력류는
키 등록자 전원)을 비교했다. 상한이 없어서 등록자가 늘수록:

- **가독성** — 비교표·아이템 카드는 행 수만큼 세로로 자라는 PNG(동적 높이 렌더). 20명이면
  20행/20카드 — 디스코드 미리보기가 축소돼 한눈에 안 들어온다.
- **조회 속도** — 대상 1명당 넥슨 호출이 필요하고 전역 4req/s 스로틀(ADR-0004) 아래서
  인원에 비례해 응답이 느려진다.

대상을 **지정하는** 경우는 파라미터 슬롯(`대상1`~`대상5`)이 이미 5명 상한을 강제하므로
문제가 없다. 경계가 없는 것은 무인자 경로뿐이다. (`/스펙`은 지정 필수 1~5명,
`/경험치`는 표시 Top 10, `/내캐릭터`는 레벨 상위 5캐릭으로 각자 경계가 이미 있다.)

## 결정 (Decision)

### 1. 무인자 실행은 **K=10명**만 비교한다 (선정 규칙은 2026-07-04 개정 — 아래 개정 노트)

- 적용: `/아이템`·`/유니온`(등록자), `/스타포스`·`/잠재`(키 등록자).
- ~~선정 기준: `Target.level`(대표 캐릭터 레벨) 내림차순~~ → **본인 포함 랜덤**(개정, 아래).
- 단일 소스: [comparison.select_with_self](../../maple_mate/bot/comparison.py)
  (`MAX_UNSPECIFIED_TARGETS = 10`). `Target`·`HistoryTarget` 둘 다 받는다(덕 타이핑).
- 대상 지정 경로는 무변경 — 슬롯 5개가 이미 상한이고, 지정한 사람은 반드시 보여야 한다.

### 2. 데이터 임베드 푸터에 한 줄 안내 (2026-07-04 상시화 개정 — 아래 개정 노트)

~~"등록자 N명 중 대표 레벨 상위 10명만 비교했어요 …" — 잘렸을 때만~~ → **인원수로 분기해 항상
표시**(개정, 아래). 이력류는 명사만 "키 등록자"로.

### 3. 이력류 무인자는 **'키 미등록' 행을 숨긴다**

기존엔 무인자 `/스타포스`·`/잠재`가 키 미등록 등록자를 "키 미등록" 부분성공 행으로 나열했다.
상한 도입 후 이 행이 슬롯을 차지하면(예: Lv.280 키 미등록이 Lv.250 키 등록자를 밀어냄) 데이터
있는 행이 밀려나므로, **무인자에선 키 등록자만 선정·표시**한다. 대상을 **지정**한 경우의
'키 미등록' 안내 행은 그대로 유지한다(부분 성공 철학 — 지정한 사람은 왜 안 나오는지 알려야 한다).

### 4. 수집 경로는 건드리지 않는다

상한은 명령 어댑터 계층(`handle_*`)에만 둔다. `get_targets`/`get_history_targets` 자체에
넣으면 `/경험치` 스냅샷 수집·백필이 같은 헬퍼를 쓰므로 리더보드 데이터가 유실된다.
이를 위해 `Target`·`HistoryTarget`에 `level` 필드를 추가했다(대표 해석 시 이미 메모리에
있던 값 — 쿼리 무변경).

## 대안 (Considered)

- **이미지 페이지네이션(10명 단위 여러 장)** — 넥슨 팬아웃은 그대로라 속도 문제가 안 풀리고,
  여러 장 PNG는 채널 도배. 기각.
- **상한 없이 렌더만 압축(폰트·행높이 축소)** — 20명 이상에서 결국 같은 문제. 기각.
- **등록순/무작위 선정** — "왜 얘가 나오고 쟤가 안 나오냐"에 답할 수 없다. 레벨 정렬은
  대표 자동선정 규칙(레벨 최고)과 같은 시각 언어라 예측 가능. 기각.

## 결과 (Consequences)

- 등록자 10명 이하 서버(현재 전부)는 화면·동작 변화 없음(안내 줄도 없음).
- 초과 서버에서 무인자 최악 팬아웃이 10콜로 고정 — 스로틀 하에서 응답 시간 상한 확보.
- `/스타포스`·/`잠재` 무인자에서 키 미등록 유저가 보이지 않게 됨 — `/키등록` 유도는
  대상 지정 경로와 명령 설명 문구가 담당.
- 홍보 사이트 명령 요약(commands.json)·튜토리얼 S10 카피가 이 결정과 동기화됐다
  (사이트 PR #54 선보정).

## 개정 (2026-07-04) — 선정 규칙: 대표 레벨 상위 → **본인 포함 랜덤** + 명령별 지표 정렬 + 푸터 상시화

초안의 "대표 레벨 상위 K명"은 상위권만 반복 노출돼 불공평하다는 사용자 판단으로 개정한다. 위
대안 절의 "무작위 선정 — 예측 불가라 기각"을 **뒤집는다**: 무인자 비교의 목적은 순위 서열이
아니라 "친구들과 가볍게 견줘 보기"이므로, 예측 가능성보다 **공평한 노출**(모두에게 뽑힐 기회)이
더 타당하다. 상한 K=10·대상 지정 무변경·이력류 키 미등록 숨김(결정 3·4)은 그대로 유지한다.

### 개정 1. 무인자 선정 = **명령 실행 본인 무조건 포함 + 나머지 랜덤**

- 상한 K=10 유지. 실행 본인은 항상 선정(자기 결과는 늘 보여야 공평 비교의 기준점).
- 나머지는 비복원 랜덤 추출(`random.sample` — 중복 구조적 불가) · **매 실행 독립**(시드 없음,
  테스트만 시드/monkeypatch 주입으로 결정적 검증). 풀 자체가 등록자(이력류=키 등록자)뿐이라
  미등록 유저가 뽑힐 여지 없음.
- **본인이 풀에 없으면** 조용히 랜덤 K명 + 임베드 푸터에 사유별 안내 한 줄:
  캐릭터 미등록 → "`/캐릭터등록` 부터", 키 미등록(스타포스·잠재) → "`/키등록` 부터",
  챌린저스 모드에서 챌 캐릭 없음 → "챌린저스 캐릭터가 없어 …".
- 단일 소스 `cap_by_level` → [comparison.select_with_self](../../maple_mate/bot/comparison.py)
  로 교체(시그니처에 실행자 `discord_user_id` 추가). 반환 = (선정 목록, 전체 N, 본인 포함 여부).

### 개정 2. 표시 정렬 = **명령별 핵심 지표**(무인자 + 지정 실행 공통)

무인자 선정이 랜덤이 됐으니 화면 정렬은 각 명령의 핵심 지표로 통일한다(조회 후 결과값 기준,
최고값 하이라이트 규칙은 기존 유지). `/아이템` = 본인 맨 앞(대상에 있을 때만) + 나머지는
무인자=랜덤 선정 순서·지정=입력 순서 / `/유니온` = 유니온 레벨 내림차순 / `/스펙` = 전투력
내림차순(지정 필수 명령) / `/스타포스` = 운빨 좋은 순(상위 % 오름차순) / `/잠재` = 사용 메소
내림차순 / `/경험치` = 기존 (레벨, exp%) 유지. (유니온·스펙·스타포스·잠재는 개정 전에도 이미
지표 정렬이라 코드 무변경, 아이템만 본인-우선 재정렬 추가.)

### 개정 3. 무인자 푸터 = **항상 표시**, 인원수로 문구 분기

기존 "잘렸을 때만"에서 상시화한다. N ≤ 10 → "등록자 전원(N명)을 비교했어요", N > 10 →
"등록자 N명 중 본인 포함 랜덤 10명을 비교했어요 · 특정 인원은 대상 지정(최대 5명)으로 볼 수
있어요". 스타포스·잠재는 명사 "키 등록자". 지정 실행에는 이 푸터 없음(종전대로).

### 개정 결과

- 등록자 10명 이하 서버(현재 전부)는 선정·순서 변화 없음(전원 비교) — 다만 푸터가 상시 표시된다
  (기존엔 안내 없음). 초과 서버에서만 매 실행 무작위 10명(본인 고정)이 바뀐다.
- `/경험치`는 랜덤 미적용(리더보드 정체성 — 레벨 Top-10 기조·매일 발송·DM 구독 payload 불변).
  대신 대상 지정(유저1~5)만 추가 — 지정 시 그 유저들의 대표 캐릭터만 표시, 미등록·데이터 없는
  지정 유저는 빼고 "N명은 미등록/데이터 없음" 안내.
- 홍보 사이트(튜토리얼 S10·commands.json·데모)는 사이트 PR2 에서 동기화(봇 배포와 순서 맞춤).
