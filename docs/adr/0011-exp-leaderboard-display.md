# ADR-0011 — 경험치 리더보드 표시 개편: 표 패널 폐기→임베드 Top3 + 그래프는 절대 레벨 유지

- **상태:** 채택 (Accepted)
- **일자:** 2026-06-24
- **관련 문서:** [CONTEXT.md](../../CONTEXT.md)(경험치 리더보드·어제 Δ), [ADR-0005](0005-exp-leaderboard-data-source.md)(누적 소스·전체 서버 순위), [leaderboard_image.py](../../maple_mate/bot/leaderboard_image.py), [broadcast.py](../../maple_mate/leaderboard/broadcast.py)
- **이력:** 그래프 디자인 개선 그릴링(2026-06-23) → 라이브 피드백 반영(2026-06-24). 직전 상태 = 절대 레벨축 라인 + 이미지 우측 리더보드 표 패널([leaderboard_graph_1503.png] 출력).

## 맥락 (Context)

경험치 리더보드 그래프의 출력이 "조잡하다"는 피드백에서 출발했다. 직전 디자인의 문제:

1. **이미지 우측 리더보드 표 패널이 폭을 절반 가까이 차지** → 주요 지표인 그래프가 좁고, 선 위 중간 점별 라벨이 서로 겹쳤다(`Lv.287 (76%)`·`(78%)`).
2. **그래프로 "누가 열심히 하나"가 안 보임** — 친구 전원 고렙(Lv.287 근처)이면 절대 레벨 라인이 평탄.

처음엔 (2)를 풀려고 **D-7 대비 정규화 '성장 레이스'**(각자 0에서 출발해 이번 주 오른 레벨만)를 시도했다. 평탄·겹침은 사라졌으나 **라이브에서 치명적 혼란**이 드러났다: 정규화 그래프의 시각적 순위(상승량 순)가 **실제 레벨 순위와 달라** "누가 1등인지" 헷갈렸다. 사용자 판단 — *"결국엔 총 레벨을 비교해야지, D-7 대비 상승량 비교는 적절치 않다."* 리더보드의 본질은 **총 레벨 줄세우기**이고, 그래프도 그 순위를 따라야 한다.

## 결정 (Decision)

**그래프는 절대 레벨을 유지하되(순위 혼동 제거), 직전 라운드의 레이아웃 개선은 살린다.**

1. **그래프 Y축 = 절대 레벨**(`progress = 레벨 + exp%/100`을 그대로). 선 높이 = 총 레벨이라 **그래프 순위 = 레벨 순위 = 임베드 순위판**(세 면이 일치, 혼동 0). 축은 데이터 실범위에 줌(작은 레벨차도 보이게), 정수 눈금(`Lv.287`). '누가 열심히'는 선의 **기울기**로 읽힌다(급등 = 많이 성장 — 챌린저스 Lv.200→272 사례에서 가파른 선으로 자명).
2. **이미지 표 패널 제거 → 그래프 전체 폭.** 순위는 **디스코드 임베드 텍스트**로 분리.
3. **선 끝 라벨 = `닉네임 Lv.287 (79%)`**(절대 레벨). 사라진 표 패널의 색↔닉 범례를 대체한다. 끝점이 붙으면 세로 분산(de-collision). **중간 점별 라벨은 전부 제거**(겹침 원인 제거).
4. **임베드 순위판 = 현재 레벨 Top3** — 메달(🥇🥈🥉) + `닉` + `Lv.287 (79%)`. **전체 서버 순위(#)·어제 Δ·그래프 안내 문구는 미표기**(사용자 피드백 — 군더더기). 그래프는 등록 전원을 그리되, 임베드 텍스트는 상위 3명으로 압축.
5. **순위 정렬 키 = (레벨, 레벨 내 exp%, 누적)** — 레벨 우선. 챌린저스 **버닝**(레벨 부스트)이 누적과 레벨을 어긋나게 해(Lv.276 캐릭의 누적 < Lv.272 캐릭의 누적) `total_exp` 단독 정렬(ADR-0005)이 챌린저스 순위를 뒤집었다(라이브 발견). 레벨 우선이면 본서버(누적=레벨 단조)·챌린저스 모두 정상이고, 그래프(`레벨+exp%/100` 정렬)와 임베드 순위가 일치한다.
6. **표시 레벨 = `character/basic` 라이브(date 무지정=최신).** 순위판 Top3·그래프 끝점 모두 '오늘 현재' 레벨로 보여준다 — `ranking/overall`(전일 누적)은 **정렬·게이트·7일 이력 스냅샷**에만 쓰고, 화면에 보이는 레벨·exp% 는 character/basic 최신값으로 덮어쓴다(`with_live_levels`). 그래프 끝엔 오늘 라이브 점을 붙여(`append_live_point`) 끝점이 임베드와 같은 '현재'가 된다. 리더보드의 본질은 '현재 캐릭터 레벨 비교'라 전일 누적이 아니라 라이브 레벨이 맞다. 라이브 조회 실패 대상은 D-1 스냅샷으로 폴백. `/경험치` 온디맨드의 '명령 시점 갱신'도 이 라이브 조회가 담당하므로 D-1 강제 재적재는 불필요(backfill 로 7일 이력 공백만 메움).

## 검토한 대안 (Alternatives Considered)

- **D-7 정규화 '성장 레이스'(각자 0 출발, 상승량만)** — *시도 후 기각.* 평탄·겹침은 해결하나 **시각 순위 ≠ 레벨 순위**라 라이브에서 "누가 1등인지" 혼란을 유발. 리더보드 본질(총 레벨 줄세우기)과 충돌.
- **순위를 이미지 표로 유지(슬림화)** — *기각.* 그래프 폭을 계속 잠식하고 한글 폰트 컨테이너 리스크가 남는다. 임베드 텍스트는 폭 0 잠식·복사 가능·모바일 친화.
- **임베드에 전체 서버 순위(#)·어제 Δ 병기** — *기각.* ADR-0005가 마련한 #를 한때 복원했으나, 사용자가 군더더기로 판단(`전체 #1,218,136`은 친구 비교에 무의미). 1일 raw exp Δ도 고렙에서 조(兆) 단위라 표기가 거칢. 둘 다 미표시, 순위판은 닉·레벨만.
- **임베드에 등록 전원 표기** — *기각.* Top3로 압축해 메시지를 간결하게(전원은 그래프가 시각적으로 커버).

## 결과 (Consequences)

**긍정**
- 그래프·임베드·실제 순위가 **레벨 기준으로 일치** → "누가 1등" 혼동 제거(핵심 피드백 해소).
- 그래프가 폭을 전부 차지(주요 지표 확대), 색↔닉 범례가 선 끝에 내장돼 표 패널 불필요. 중간 라벨 제거로 겹침 해소.
- 임베드 순위판이 닉·레벨 Top3로 간결.

**부담 / 잔류**
- **전원 동레벨대면 라인이 평탄** — 절대축의 본질적 한계(Lv.287 클러스터는 거의 평행). 정확한 값은 선 끝 라벨이 보완하고, 사용자가 이 트레이드오프를 택했다(순위 정합 > 추세 과장). '누가 열심히'는 기울기로만 읽힌다.
- **`build_rows`의 어제 Δ·world_rank 가 표시 미사용** — 게이트·향후용으로 남김(제거 시 service·테스트 동반 수정이라 surgical 위반).
- **챌린저스 빈 좌측** — 넥슨이 6/19부터만 데이터라 6/16~18 구간은 점이 없다(정상).
- **혼합 시간축** — 그래프 끝점(오늘)은 character/basic 라이브, 그 이전 점들은 D-1 스냅샷(전일 마감)이다. 지표(레벨+exp%/100)는 동일해 일관되지만, 오늘 점은 조회 시점 스냅이라 같은 날 여러 번 보면 조금씩 다를 수 있다(정상). 임베드·그래프 끝·실제 레벨은 항상 서로 일치.
- **라이브 조회 콜 추가** — 발송·명령마다 character/basic 을 realm 대표 수만큼 호출(무지정=최신, 30분 캐시·쿨다운·전역 스로틀로 바운드). `ranking/overall`(누적·world_rank)은 정렬·이력에만 남고 표시엔 안 쓰여 약간 잉여지만, 7일 이력 스냅샷 소스라 유지.
- **챌린저스 버닝 → 레벨≠누적** 이 드러나 ADR-0005 의 total_exp 히든키 가정을 레벨 우선으로 보정 — 향후 버프 서버에도 안전.

## 개정 (Amendment) — 2026-06-27: Top3→Top10 + 순위 공식 단일화

표시 개편 후속 그릴링에서 두 가지를 바꿨다.

1. **표기 상한 Top3 → Top10, 두 표시면 모두.** 결정 4가 "임베드는 Top3, 그래프는 등록 전원"으로 비대칭이었는데, 등록자가 많은 길드에서 그래프가 과밀해지고 임베드가 너무 적었다. 이제 **순위판·그래프 모두 상위 10명**(`broadcast._TOP_N = 10`)으로 통일한다. 등록자 10명 초과면 둘 다 같은 10명으로 캡하고(그래프 `series` 를 `display_rows[:10]` 멤버로 필터), 10명 이하면 있는 만큼 보여준다. 임베드는 메달(🥇🥈🥉) 뒤 4위부터 `4.`~`10.` 번호.
2. **순위 정렬 키에서 `total_exp` 완전 제거 → `(레벨, 레벨 내 exp%)` 단일 공식.** 결정 5의 키가 `(레벨, exp%, 누적)` 3단이었으나, 표시 순위는 `with_live_levels`(라이브 레벨, `(레벨, exp%)`)가 재정렬하므로 `total_exp` 는 사실상 사문(死文)이었고, **그래프(`progress=레벨+exp%/100`)는 `total_exp` 를 볼 수 없어** 두 면이 다른 공식을 쓰는 것처럼 보였다(사용자 지적 — "왜 임베드랑 그래프 계산이 다르냐"). `service._rank_key(level, exp_rate)` 로 추출해 `build_rows`·`with_live_levels` 가 **같은 키**를 쓰고, 그래프 멤버도 그 순위(`display_rows`)에서 파생해 **임베드와 항상 동일한 10명·동일 순서**가 된다. 동(同)레벨·동 exp% 는 안정 정렬(입력 순서)로 두며, `total_exp` 타이브레이크는 폐기(그래프가 못 보는 키라 통일 불가).

**그래프 라인 팔레트**도 8색 → **10색**으로 확장(`_LINE_COLORS`) — 10개 라인 전원이 고유색을 갖도록(마커는 8개 유지, 주기가 달라 상위 10개까지 색+마커 조합 충돌 없음).

**영향 파일:** [broadcast.py](../../maple_mate/leaderboard/broadcast.py)(`_TOP_N`·그래프 series 캡), [service.py](../../maple_mate/leaderboard/service.py)(`_rank_key`), [leaderboard_image.py](../../maple_mate/bot/leaderboard_image.py)(10색). 결정 4·5의 본문은 역사 기록으로 남기고 본 개정이 우선한다.
