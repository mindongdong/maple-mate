## 맥락 (Context)

`/스타포스`·`/잠재`는 개인 키로 **계정 전체(부캐 포함) 이력을 합산**한다(ADR-0007). 그런데 표시 계층은 그 합산값을 **대표 캐릭터 닉**으로 라벨링한다 — 행 `대상` 컬럼·임베드 범례·실패줄 모두 메이플 닉이다. 이는 "이 행 = 이 캐릭터"라는 오해를 만든다. 실제 집계 단위는 **디스코드 유저의 계정**(키 1개)인데 캐릭터 1명의 이름표가 붙는 것이다.

사용자 요구는 세 가지다:
1. 집계 단위가 캐릭터가 아니라 **디스코드 유저(계정)**이므로 결과 표·임베드에 **캐릭터 이름이 들어가면 안 된다**.
2. 계정 전체 데이터라서 **본서버/챌린저스 모드 파라미터가 불필요**하다.
3. 잠재는 **잠재능력 / 에디셔널 잠재능력**으로 나뉘는데, 등업 표시가 둘 다 제대로 나오는지·구분되는지 점검.

점검 결과 **요구3은 버그**였다: 등업 집계가 종류와 무관하게 항상 `before_potential_option`(잠재능력)만 본다([potential_service.py](../../maple_mate/history/potential_service.py) `aggregate_potential`). 에디셔널 등업은 → 잠재 등급으로 **오집계되거나 누락**되고, 표/보조 어디서도 잠재 vs 에디 **구분이 없다**. (반면 `/비틱`은 이미 `_kind_of`로 종류를 가른다.)

긴장점: 봇은 [`Intents.default()`](../../maple_mate/bot/core.py)로 **members 특권 인텐트가 없어** 서버 전체 조회 시 등록자의 디스코드 표시명을 `get_member`로 안정적으로 얻지 못한다(캐시 미스). 캐릭터 닉이 DB에 있어 지금까지 그걸 라벨로 쓴 것이다. 요구1을 만족하려면 표시명 소스를 확보해야 한다.

## 결정 (Decision)

**두 명령을 "캐릭터 비교"가 아니라 "계정(디스코드 유저) 비교"로 정렬한다 — 라벨을 디스코드 유저로, 모드를 제거, 잠재/에디 등업을 분리.**

1. **다인 비교 유지, 라벨만 계정화.** 명령은 여전히 서버 등록자(미지정=전원, 또는 지정 멤버) 비교다 — 각 행 = 디스코드 유저 1명. 바뀌는 건 **행 라벨**: 대표 캐릭터 닉 → **디스코드 유저**. 캐릭터 이름은 표·범례·실패줄 어디에도 노출하지 않는다(요구1).

2. **표=서버 표시명, 범례=표시명 @멘션, 공유 헬퍼 무변경.** PNG 표 `대상` 셀엔 디스코드 **서버 표시명**(길드 닉 우선), 임베드 범례엔 `표시명 @멘션`(멘션은 클라이언트단 렌더라 캐시 불요 — 식별은 항상 정확). 구현은 명령 계층에서 `discord_user_id→표시명`을 풀어 행/범례/실패 outcome의 `Target.nickname`에 **표시명을 주입**한다 — `owner_legend`·`_failure_lines`는 손대지 않아도 자동 반영된다(스펙·아이템 등 캐릭터 닉을 쓰는 다른 명령에 영향 0). 서비스 계층은 디스코드 무관 유지.

3. **members 인텐트 활성화 + `get_member`, 이탈 유저는 제외.** 표시명을 안정적으로 얻기 위해 봇에 **Server Members Intent**를 켠다(`Intents.members=True` + Discord 개발자 포털 토글). 인텐트가 있어도 **서버를 떠난 등록자**는 `get_member=None` → **전원 조회 결과에서 제외**한다(서버 비교/리더보드 성격상 현재 멤버만, 요구1대로 캐릭터 닉 폴백 없음). 이는 동작 변경(이전엔 DB 기준 포함)이다.

4. **모드(realm) 파라미터 제거 — 본+챌 한 계정 합산.** 두 명령에서 `모드`를 떼고 realm 필터를 없앤다 — 개인 키가 반환하는 계정 전체(본서버+챌린저스)를 한 값으로 합산한다(요구2). orphan이 되는 realm 코드(`attempts_in_realm`·`records_in_realm`·`get_realm_by_nickname`, 전부 이 둘 전용)와 `🏆 챌린저스` 제목 프리픽스를 **완전 제거**한다.

5. **잠재/에디 등업 정정 — 종류별 from-등급 2버킷.** 레코드 종류를 `_kind_of`(에디 큐브/`potential_type` "에디" 판정, `/비틱`과 단일 출처 공유)로 가르고 **에디 = `before_additional_potential_option` / 잠재 = `before_potential_option`** 최고 등급에서 from-등급을 추출해 **두 버킷으로 분리** 집계한다. `item_upgrade_result=="성공"` + from ∈ {레어·에픽·유니크} 규칙은 종류마다 동일.

6. **표 2컬럼 + 보조 2줄로 구분.** 비교표 `등업` 컬럼을 **`잠재 등업` / `에디 등업` 2컬럼**으로 나눠 각각 도달(to) 등급 GradeBadges로(0건은 `—`). 단일 대상 보조 `⬆️ 등업 진행`도 `잠재:` / `에디:` 2줄로 분리한다. GradeBadges 렌더러·등급 색·도달등급 매핑은 그대로 재사용(렌더러 변경 0).

## 검토한 대안 (Alternatives Considered)

- **본인 단일 계정 전용 명령으로 축소(비교 제거)** — *기각.* 요구1은 "캐릭터명 제거"지 "비교 제거"가 아니다. 서버 비교(누가 더 운 좋은지/많이 썼는지)는 명령의 핵심 가치라 라벨만 계정화한다(결정 1).
- **표시명 소스 = `fetch_member` 호출(인텐트 없이)** — *기각.* 등록자 N명당 HTTP N콜 + 레이트리밋·이탈 시 NotFound. members 인텐트(1회 ops)가 캐시에서 공짜로 안정 해석(<100서버 인증 불요).
- **표시명 소스 = `get_member` 최선노력 + 미스 폴백 라벨** — *기각.* 인텐트 없이는 미스가 흔해 표 라벨이 자주 플레이스홀더. 식별은 범례 멘션으로 항상 정확하지만 표 셀이 비어 보임. 인텐트로 미스를 구조적으로 없애는 쪽 선택.
- **표시명을 등록 시 DB에 저장 + 갱신** — *기각.* 마이그레이션 + 표시명 드리프트 관리. 라이브 `get_member`가 항상 현재값이라 더 단순(인텐트 비용만 지불).
- **이탈 유저를 `(서버 이탈)` 플레이스홀더로 포함** — *기각.* 누구인지 알 수 없는 행이 생긴다. 현재 서버 멤버만 비교가 더 깔끔(결정 3).
- **등업 표시: 한 컬럼에 잠/에 2줄 라벨** — *기각.* 표 폭은 절약하나 GradeBadges에 2줄·라벨 렌더 추가 필요. 2컬럼 분리가 기존 뱃지 셀을 그대로 재사용해 구현 최단(결정 6).
- **모드 제거 없이 챌린저스 합산만 추가** — *기각.* 모드 파라미터 존속은 "계정 전체"라는 새 의미와 모순(어느 realm을 고른다는 토글이 의미 없음). 파라미터째 제거가 정합.
- **ADR 없이 코드+작업지시서만** — *기각.* 모드 제거는 ADR-0009(누수 0·realm 분리)의 **의도적 부분 되돌림**이라 "왜 이 두 명령만 realm을 합치나"의 맥락 기록이 필요.

## 결과 (Consequences)

**긍정**
- 표시가 집계 단위(계정=디스코드 유저)와 일치 — "행 = 캐릭터" 오해 제거(요구1). 범례 멘션은 캐시 불요라 식별 항상 정확.
- 모드 제거로 두 명령의 표면·코드가 단순해짐(파라미터 1개·realm 헬퍼 3개·제목 분기 삭제, 요구2).
- 에디셔널 등업이 처음으로 정확히 카운트되고 잠재와 구분 표시됨 — **기존 오집계 버그 해소**(요구3). `_kind_of` 단일 출처로 `/비틱`과 정합.

**부담 / 잔류**
- **members 특권 인텐트 도입** — 봇 최초의 특권 인텐트. 배포 전 Discord 개발자 포털 토글 + 재배포 필수(미설정 시 표시명 미해석). 부팅 시 길드 청크로 소폭 시작 지연·메모리(소규모 무방). 프라이버시상 봇이 전체 멤버 목록을 받게 됨(이미 개인 키 보관 봇이라 한계 비용 작음).
- **이력류 realm 분리 비대칭이 더 줄되 비대칭은 남음** — `/스타포스`·`/잠재`는 이제 realm 무관(합산), `/비틱`만 챌린저스 대표 닉 교체로 realm 인지(ADR-0009 결정 4 표가 `/비틱` 한 줄로 축소). "왜 비틱만 realm을 가르나"는 비틱이 *대표 자랑* 성격이라(계정 비교 아님) 유지.
- **이탈 유저 제외 = 동작 변경** — DB 등록자라도 서버를 떠났으면 표에서 사라진다(이전 포함). 의도된 것이나 "내 친구 왜 안 나와"의 답이 본 ADR.
- **CONTEXT.md 갱신 필요** — 모드 명령 6개→4개, 이력류 표시 라벨(캐릭터 닉→디스코드 유저), 등업(잠재/에디 분리), realm 분리 비대칭 표. 구현 시 반영(작업지시서 #5).
