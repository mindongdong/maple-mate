# ADR-0014 — 스케줄러 숙제 카테고리 필터: opt-out 4묶음 (온디맨드 무상태 + 구독 지속 병합)

- **상태:** 채택 (Accepted)
- **일자:** 2026-06-28
- **관련 문서:** [CONTEXT.md](../../CONTEXT.md)(숙제 카테고리 필터·스케줄러 알리미), [ADR-0012](0012-scheduler-reminder-per-user-dm.md)(per-user DM 구독 모델 — 이 ADR이 구독에 **지속 표시 선호**를 더함), [ADR-0013](0013-scheduler-field-derived-categories.md)(필드 파생 카테고리 — 본 필터의 묶음 대상), [modes.py](../../maple_mate/bot/modes.py)(무상태 파라미터 철학), [service.py](../../maple_mate/scheduler/service.py)·[broadcast.py](../../maple_mate/scheduler/broadcast.py)·[commands.py](../../maple_mate/scheduler/commands.py)·[models.py](../../maple_mate/scheduler/models.py)
- **이력:** `/grill-with-docs` 그릴링(2026-06-28) — 본 문서로 결정 7건 확정.

## 맥락 (Context)

`/스케줄러`·스케줄러 알림 DM은 등록 캐릭터별 임베드 1개에 [필드 파생 카테고리](0013-scheduler-field-derived-categories.md) 8개(일일 퀘스트·일일 콘텐츠·주간 퀘스트·주간 콘텐츠·길드 콘텐츠·주간 보스·일간 보스·월간 보스)를 **비어있지 않은 것 전부** 표시한다(캐릭터당 메시지 1개, 최대 10개). 사용자는 "이걸 다 보는 것보다 **보고 싶은 카테고리만** 골라 보고 싶다"고 요청했다.

긴장점: 이 봇의 모드 파라미터는 의도적으로 **무상태**다([modes.py](../../maple_mate/bot/modes.py): "명령별 무상태 파라미터 — 공개 봇에서 숨은 토글 사고를 피한다"). 그러나 **알림은 발송 시점에 상호작용이 없다**(정각 cron DM) — "사용자가 선택"을 알림에 적용하려면 선호를 **지속**해야 하고, 이는 무상태 철학과 정면으로 부딪힌다. 두 표면(온디맨드/알림)을 모두 지원하라는 요구가 이 ADR을 강제했다.

## 결정 (Decision)

**숙제를 사용자 어휘 4묶음으로 묶어 opt-out 필터를 건다. 온디맨드는 무상태로, 알림은 구독에 선호를 지속(병합)한다.**

1. **4묶음(일일·주간·보스·길드), opt-out.** 8개 필드 파생 카테고리를 사용자 어휘 4묶음으로 매핑한다 — 일일={일일 퀘스트+콘텐츠}, 주간={주간 퀘스트+콘텐츠}, 보스={일간·주간·월간 전 cycle + 기타 cycle}, 길드={길드 콘텐츠}. **기본은 전부 켜짐** — 아무것도 지정 안 하면 8개 전부 표시(기존과 100% 동일, 하위호환).
2. **두 표면 모두 4개 on/off 파라미터**(`일일`/`주간`/`보스`/`길드`, 값 `켜기`/`끄기`). select 메뉴 컴포넌트가 아니라 기존 [켜기/끄기 Choice 패턴](../../maple_mate/notification/commands.py)을 재사용한다.
   - **온디맨드 `/스케줄러`: 무상태.** 안 적은 파라미터 = `켜기`(보임). 매 호출이 완전 선언이고 저장 상태를 읽거나 쓰지 않는다 — 무상태 철학 보존.
   - **알림 `/스케줄러알림 켜기`: tri-state 병합.** 파라미터는 `켜기`/`끄기`/`미지정(None)`. 미지정 = **기존 저장값 유지**, 켜기/끄기 = 델타. 신규 구독의 baseline = 전부 켜짐. 시각만 바꾸려 재실행해도 꺼둔 묶음이 유지된다(read-modify-write upsert).
3. **숨김 시 헤드라인·상태색은 보이는 묶음만 재집계.** 부제 `🔥 남은 숙제 N개 (완료/총)`와 잔여-0 초록/오렌지 상태색을 **표시 중인 묶음**으로만 다시 계산해 화면과 헤드라인을 일치시킨다.
4. **저장은 ENABLED가 아니라 EXCLUDED 집합.** 구독 행에 제외 묶음을 단일 컬럼(예: `"boss,guild"`, `NULL`=제외 없음=전부 표시)으로 둔다. **하위호환**(기존 행 NULL = 전부 표시, 행동 변화 0) + **상위호환**(나중에 5번째 카테고리가 생겨도 기존 구독자에게 기본 표시 — opt-out 보존).
5. **극단 가드.** ① 4묶음 전부 꺼짐 → 온디맨드는 빈 메시지 대신 "표시할 카테고리를 최소 하나는 켜주세요" 안내, 알림 `켜기`는 (병합 결과 기준) 거부(fail-fast, 기존 키·캐릭터 가드와 동류). ② **필터 후 빈 캐릭터 스킵** — 기존 `is_empty`("등록 숙제 0개면 발송 안 함")를 **필터된 뷰**로 확장.
6. **넥슨 페치는 불변.** 필터는 **표시 전용**이다. 캐릭터별 full state는 그대로 페치하고(스로틀·콜 수 동일) 임베드 조립 단계에서만 묶음을 가린다. 비용 절감은 없고, 가독성만 개선한다.
7. **기록은 신규 ADR(본 문서).** ADR-0012(구독 모델)·0013(표시 카테고리) 양쪽에 걸치는 독립 결정이라 두 개정 노트로 쪼개지 않고 단일 ADR로 둔다. 0012에는 "구독이 지속 표시 선호를 갖게 됨" 개정 포인터만 더한다.

## 검토한 대안 (Alternatives Considered)

- **8개 개별 토글 / 타입축(퀘스트·콘텐츠·보스·길드) 4묶음** — *기각.* 8개는 조작·저장 모두 과함. 타입축은 메이플 플레이어의 "일일/주간" 세션 계획 멘탈모델과 덜 맞음.
- **다중선택 select 메뉴 컴포넌트** — *기각.* 온디맨드가 캐릭터당 메시지 N개라 드롭다운의 귀속(어느 메시지가 필터를 소유?)이 모호. on/off Choice 파라미터(전역 적용)가 더 단순.
- **전체 선언(켜기 재실행마다 전체 재저장)** — *기각.* 시각만 바꿔도 꺼둔 필터가 리셋되는 부작용. 사용자가 병합을 선택(시각 변경과 필터 변경의 분리).
- **온디맨드·알림 선호 공유(마지막 /스케줄러 필터를 알림에도 적용)** — *기각.* 입력은 줄지만 "숨은 토글"이라 무상태 철학([modes.py](../../maple_mate/bot/modes.py)) 정면 위반.
- **enabled 집합 저장 / 컬럼 4개** — *기각.* enabled 저장은 신규 카테고리가 기존 구독자에게 숨겨지는 상위호환 문제. 컬럼 4개는 스키마 비대 — 단일 제외집합 컬럼이 최소.
- **ADR 없이 코드+핸드오프만** — *기각.* "왜 스케줄러 구독만 지속 상태인가"가 무상태 철학과 충돌해 맥락 기록이 필요.

## 결과 (Consequences)

**긍정**
- "보고 싶은 것만" 요구 충족 + 노이즈 감소(긴 임베드 축소). 기본값이 기존과 동일해 무회귀.
- 기존 Choice 파라미터 인프라 재사용(신규 컴포넌트 0). 사용자 어휘(일일/주간/보스/길드)로 직관적.
- 제외집합 저장으로 하위·상위호환 동시 확보.

**부담 / 잔류**
- **스케줄러 구독이 봇 최초의 지속 표시 선호** — 무상태 철학의 예외다. "왜 여기만 상태를 갖나"의 답이 본 ADR(알림은 발송 시점 상호작용 부재).
- **병합은 read-modify-write + tri-state 파라미터** 도입 — 블라인드 upsert보다 한 단계 복잡. 온디맨드(무상태)와 알림(병합)의 "미지정" 의미가 다름(전자=보임, 후자=유지) — "안 적으면 현재 상태 불변"으로 통일 설명.
- **8필드→4묶음 매핑이 코드 1곳 고정** — 넥슨이 신규 cycle/타입을 추가하면 매핑 갱신 필요(필드 파생은 ADR-0013, 묶음 매핑은 본 ADR 소관).
- **헤드라인 재집계로 같은 캐릭터가 필터에 따라 다른 "남은 N"** 을 보일 수 있음(의도된 동작 — 보이는 것과 일치 우선).
