# 메이트 웹사이트 — 비주얼 디자인 세션 핸드오프

> **이 문서의 목적**: 다른 세션에서 메이트 웹사이트의 **비주얼 디자인**을 이어서 논의하기 위한 자립형 브리핑.
> 구조·스택·톤 *방향*은 이미 확정됐다(아래 §1). 이 세션은 **구체적 디자인 시스템**을 결정한다.
> 진행 방식: `grill-me`로 §3 결정 트리를 하나씩, 추천안 제시하며 해소 → 필요 시 `designer`/`prototype`으로 목업.

---

## 0. 한 줄 컨텍스트

**메이트** = "같이 메이플하는 친구" 컨셉의 메이플스토리 디스코드 봇. 이 웹사이트는 **홍보 + 기능 문서(개발문서/위키 스타일)**.
차별점: 유저 간 데이터 비교(리더보드·지출 견주기) + 개인 스케줄러 비서. 경쟁자 **엔버봇**(abbot.kr, 디스코드 공식인증·42명령·범용 조회+계산기/시뮬+뉴스알리미)과 **톤·감성 차별**이 목표.

## 1. 이미 확정된 것 — 디자인의 제약조건 (재론 금지)

grill-me 8결정 (메모리 `website-docs-plan` 참조):

| 항목 | 확정값 | 디자인 함의 |
|---|---|---|
| 목적 | 문서·위키 우선 + 상단 랜딩 히어로 | 디자인 무게중심 = 스캔 잘 되는 문서. 히어로는 전환용 1스크린 |
| 스택 | Nextra (Next.js/MDX) → Vercel | **디자인은 Nextra 테마 커스터마이즈 범위 안에서**. 완전 커스텀 아님 |
| 톤 | **중립 개발문서 베이스 + 브랜드 액센트** | 본문=중립·신뢰·가독. 따뜻함은 랜딩·브랜드컬러·콜아웃·마스코트에만 |
| 폰트 | Pretendard (한글 본문) | 코드/모노는 별도 지정 필요 |
| 미디어 | 데모 서버 재캡처 스크린샷 | 실데이터 노출 금지. 스샷 프레임/배경 일관 디자인 필요 |
| 도메인 | 커스텀 도메인 + OG 이미지 | **OG 이미지 디자인은 이 세션 범위** |
| 언어 | KO 전용 | i18n 레이아웃 고려 불필요 |
| 범위 | 린 MVP + 개인정보 1장 | 아래 IA만 디자인 |

**IA / 페이지 트리 (MVP)**
```
/ 랜딩          히어로(소개문+초대CTA) · 3기둥(비교·비서·함께) 스샷 · 5분시작 티저
시작하기        ① 봇 초대 ② 5분 온보딩(/캐릭터등록→/키등록→/대표지정) ③ 넥슨 개인 API 키 발급·등록
명령어          7그룹: 등록·관리 / 스펙·장비 / 이력 / 비틱 / 리더보드 / 스케줄러숙제 / 알림설정
개념            스펙류 vs 이력류 · 개인 API 키가 필요한 이유 · 챌린저스 서버 모드
개인정보·보안   넥슨 API 키 Fernet 암호화 보관
```

**확정 소개문 (랜딩 히어로 카피 — 그대로 사용)**
> 메이트는 이름 그대로 같이 메이플하는 친구 같은 디스코드 봇입니다. 유니온·스펙·경험치 리더보드와 스타포스·잠재 지출 비교로 서로의 성장을 겨루고, 일일·주간·보스 숙제는 스케줄러가 DM으로 챙겨줍니다.
>
> (본문 4문단은 메모리 `service-launch-copy` 및 대화 기록에 확정본 존재 — 등록·리더보드 / 스타포스·잠재 집계 비교 / 스케줄러 DM / 썬데이·공지알리미 + 마무리 CTA)

## 2. 명령어 권한 배지 체계 (디자인에 반영할 기존 시각 언어)

`guide/commands.py`가 이미 쓰는 3단계 — 웹 배지 디자인의 소스:
- 🔓 **키 불필요** (스펙류): /스펙 /아이템 /유니온
- 📜 **개인 API 키 필요** (이력류): /스타포스 /잠재 /스케줄러
- 🛡 **서버 관리 권한**: /경험치알림 /썬데이 /공지알림

## 3. 이 세션에서 결정할 것 — 디자인 결정 트리

grill-me로 순차 해소 (각 항목 추천안 제시):

1. **브랜드 아이덴티티** — 메이트를 시각적으로 무엇으로? 로고/워드마크 형태, 마스코트 유무·스타일(친구 컨셉 캐릭터 vs 순수 타이포), 톤 키워드(따뜻·아기자기 vs 깔끔·신뢰).
2. **컬러 시스템** — 브랜드 액센트 컬러 1~2개 선정(메이플 IP색 회피/차용 여부), 중립 그레이 스케일, 다크/라이트 팔레트, 권한 배지 3색.
3. **타이포그래피 스케일** — Pretendard 웨이트·본문/헤딩/코드 스케일, 라인하이트(한글 가독), 모노 폰트.
4. **랜딩 히어로 구성** — 1스크린 레이아웃(카피 위치·초대 버튼·데모 스샷/움짤·3기둥 카드), CTA 위계, 스크롤 이후 섹션 흐름.
5. **명령어 페이지 컴포넌트 패턴** — 명령 단위 카드/섹션 규격(제목·권한 배지·1줄 설명·스샷·예시), 그룹 내비게이션, 스샷 프레임 스타일.
6. **스크린샷 프레임 규격** — 배경·라운드·그림자·디바이스목업 여부, 디스코드 다크 UI와의 조화, 캡션 스타일. (데모 서버 캡처 시 그대로 적용할 규격)
7. **다크/라이트 + 반응형** — 기본 모드, 토글, 모바일 문서 내비(카톡에서 열 확률 높음 → 모바일 우선 점검).
8. **OG / 링크 프리뷰 이미지** — 카톡·디코 공유용 1200×630 디자인(로고·태그라인·스샷 썸네일).
9. **아이콘/이모지 정책** — 기존 그룹 이모지(📝⚔️📜🎴📈🗓🔔) 유지 vs 아이콘셋 통일.
10. **모션/인터랙션** (선택) — 히어로 등장·스크롤 애니메이션 최소 범위.
