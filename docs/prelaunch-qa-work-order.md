> **1) /가이드 → 웹사이트 링크 전환**, **2) 라이브 QA 순회**,

## 요구사항 1 — /가이드 웹 링크 전환

### 확정 결정 (그릴링 5건)

| # | 질문 | 결정 |
|---|------|------|
| 1 | 명령 존치 형태 | **축소 임베드 + 링크 버튼** — 명령 유지(헬스체크 역할 보존), 상세 안내는 웹으로 위임 |
| 2 | 임베드에 남길 내용 | **① 봇 한줄 소개 + ② 등록 순서**(/캐릭터등록→/키등록→/대표지정)만. 🔓/📜 키 구분·챌린저스 모드 안내는 웹으로 |
| 3 | 버튼 구성 | **1개만** — "명령어 전체 보기" → `https://maplemate.site/commands` |
| 4 | 6그룹 필드 | 전부 제거 (임베드 드리프트 가드의 존재 이유 소멸) |

### 구현 지시

`maple_mate/guide/commands.py`:

- `_ONBOARDING` 을 ①②만 남기고 축소. `_GROUPS` 튜플 삭제.
- `build_guide_embed()` 는 필드 없는 임베드 반환. 푸터의 "재호출: /가이드"
  안내는 유지, "각 명령 사용법은 / 입력 시 표시돼요"도 유지 무방.
- 모듈 상수 `COMMANDS_URL = "https://maplemate.site/commands"` 추가.
- 링크 버튼: `discord.ui.View` + `discord.ui.Button(style=discord.ButtonStyle.link,
  label="📖 명령어 전체 보기", url=COMMANDS_URL)`. 링크 버튼은 콜백 없음 —
  `bot/embeds.py` 의 View 전례 참고. 응답은 `embed=..., view=..., ephemeral=True`.
- 모듈 docstring 갱신: "상세 안내는 웹사이트로 위임, 임베드는 온보딩 최소본"
  으로 존재 이유 재서술.

`tests/test_guide.py` 정리:

- **삭제**: `test_guide_covers_all_top_level_commands`(임베드 드리프트 가드 —
  커버리지 의무는 `tests/test_website_command_drift.py` 의 봇트리↔commands.json
  양방향 가드가 단독 승계), `test_guide_mentions_challengers_mode`(④ 제거로
  소멸), `test_guide_alert_groups_unified_and_sunday_renamed` 중 임베드 문구
  단언 부분(트리 단언 `썬데이 is None` 은 존치 가치 판단 후 이전).
- **유지**: 등록/핑제거·비틱 숨김·ephemeral 테스트.
- **추가**: 응답 view 의 버튼이 link 스타일이고 URL == `COMMANDS_URL` 단언 +
  임베드에 등록 순서 3명령(`캐릭터등록·키등록·대표지정`)이 등장 단언.

검증: `pytest` 전체 그린 + ruff clean. 이후 QA 순회(요구사항 2)에서
/가이드 실응답으로 버튼 동작 눈확인.

## 요구사항 2 — 라이브 QA 순회

### 확정 결정 (그릴링 5건)

| # | 질문 | 결정 |
|---|------|------|
| 1 | 방식 | **혼합** — Claude 가 체크리스트 작성 + 서비스 레이어 실넥슨 선검증, 유저가 디스코드에서 순회 |
| 2 | 환경 | **로컬 봇을 데모 서버에 연결** (운영 배포 상태와 무관, 수정→재확인 루프 빠름) — 세부는 아래 "QA 환경·시드 데이터" |
| 3 | 이슈 처리 | **트리아지 분기** — 명백한 버그·오타는 즉시 수정 후 같은 세션 재확인, 설계 판단 필요 건은 이슈 로그에 기록 → QA 후 그릴링 |
| 4 | 크론 발송류 | **단위테스트 신뢰로 생략** (경험치알림·공지알림·썬데이알림·스케줄러 DM 실발송은 이번 순회 범위 밖) |
| 5 | 깊이 | **정상 + 게이트 에러** — 명령별 정상 1회 + 전제 미충족 게이트(미등록·키없음) 응답, 챌린저스 모드 파라미터 있는 명령은 모드 1회 추가. 약 25~30항목 |

### QA 환경·시드 데이터 (유저 제공, 2026-07-02)

- **실행**: `docker compose up --build` — 로컬 도커 스택(app+db, `docker-compose.yml`).
  로컬 `.env` 의 봇 토큰은 **테스트 봇**(Railway 운영 봇과 별개)에 연결돼 있어
  운영과 완전 격리. DB 도 로컬 Postgres(호스트 5433) 볼륨.
- **시드 데이터**: 캐릭터 등록 = 본서버 1 + 챌린저스 서버 1. 개인 API 키 등록 =
  디스코드 유저 3명(섭외한 테스터). QA 순회는 이 데이터를 사용한다.
- **주의**: 게이트 에러 항목(미등록 유저·키 없는 유저 지목)은 시드 3인에
  해당자가 없으므로, 등록하지 않은 디스코드 계정 1개를 지목 대상으로 쓴다
  (등록할 필요 없음 — 게이트 응답만 확인).

### 순회 대상 (16개 최상위 명령, 사이트 문서 그룹 기준)

| 그룹 | 명령 | 정상 | 게이트 에러 | 모드 |
|------|------|------|------------|------|
| 등록·관리 | 가이드 · 캐릭터등록 · 키등록 · 대표지정 · 캐릭터목록 | ✔ | 대표지정/목록: 미등록 상태 | — |
| 스펙·장비 | 스펙 · 아이템 · 유니온 | ✔ | 미등록 유저 지목 | 챌린저스 |
| 이력 | 스타포스 · 잠재 | ✔ | 키 없는 유저 | — (ADR-0015 계정 합산) |
| 리더보드 | 경험치 | ✔ | — | 챌린저스 |
| 스케줄러 | 스케줄러 · 스케줄러알림 켜기/끄기 | ✔ | 키 없음 | — |
| 알림 설정 | 경험치알림 · 공지알림 · 썬데이알림 (켜기/끄기) | ✔ | — | — |

세부 체크리스트(항목별 기대 응답 포함)는 순회 직전에 코드 기준으로 작성해
별도 문서로 뽑는다. 이 표는 커버리지 골격.

### 진행 순서

1. ~~요구사항 1(가이드 링크)·3(총 포스 제거) 구현~~ — **현 세션에서 완료** (QA 순회가 새 동작을 검증하도록 선행)

## 요구사항 3 — /스펙 단일 상세 "총 포스" 제거 (QA 피드백 #1)

/스펙을 단일 캐릭터로 쓰면 "장착 심볼" 필드가 아래처럼 나온다:

```
총 포스 1790
아케인 6 · 어센틱 6
```

**포스 줄을 아예 제거**한다(유저 판단: 표시가 부적절). 분류별 개수 줄
(`아케인 6 · 어센틱 6`)은 유지.

### 구현 지시

- `maple_mate/character/commands.py` `_render_spec_section` 의 "장착 심볼"
  분기: `총 포스 **…**\n` 줄 삭제 → categories 만 반환 (심볼 없으면 기존
  "없음" 유지).
- 이 변경으로 `total_force` 의 유일한 표시 소비처가 사라진다 →
  `character/service.py` `SymbolSummary.total_force` 필드와 `_summarize` 의
  합산 로직, `tests/test_character_spec.py` 의 total_force 단언 3곳도 같이
  제거(내 변경이 만든 orphan 정리). 분류별 counts 로직은 무변경.
- 다인 비교 경로는 total_force 를 쓰지 않으므로 무영향.

검증: pytest 그린 + QA 순회에서 /스펙 단일 실행으로 눈확인.
