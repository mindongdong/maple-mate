## 1. 결정 로그

### D1 — 톤 축 & 마스코트 방향 ✅
**결정: 깔끔·신뢰 베이스 + 미니 마스코트(액센트 레이어).**

- 본문 = 중립 dev-docs. 따뜻함은 액센트(컬러·콜아웃·마스코트)로만.
- 마스코트 = **단순 심볼 수준**(풀 일러스트 아님). 히어로 / OG / 빈 상태 / 404 에만 등장, 문서 본문에는 넣지 않음.
- 근거: (1) 문서-중립 원칙이 이미 고정 → 무거운 마스코트는 자기모순. (2) 엔버봇 상대로 out-polish가 out-cute보다 방어 가능(일러스트 예산 없음). (3) "친구" 보이스는 카피 + 액센트 1색 + 작은 마크로 충분·저비용·IP 안전.
- 기각: 순수 타이포(엔버봇과 따뜻함 차별 약화) / 풀 일러스트 캐릭터(일러스트 비용 + 메이플 팬아트 IP 리스크 + 문서-중립 원칙과 충돌).

### D2 — 마스코트: 버섯 캐릭터 ✅
**결정: 주황버섯 갓(cap) 차용 + 얼굴은 메이트 고유.** 소스 시안 = `icon.png`(주황 갓 + 크림색 얼굴-바디 + 큰 눈·볼터치).

- **IP 자세**: 갓은 주황버섯 그대로 차용, 얼굴(표정·눈·정체성)만 메이트 오리지널로 교체 → 즉각 메이플 인지도 유지하면서 캐릭터 자체는 소유 가능. 근거: 넥슨 OpenAPI 등록 서비스들이 이미 메이플 IP 캐릭터를 로고에 널리 사용 → 넥슨의 de-facto 관용 확인(사용자 조사). 등록 서비스 맥락에서도 방어 가능 수준.
- **두 폼 시스템**(production 필수):
  - **풀 폼**(렌더드: 그라데이션·볼터치·반짝 눈) = 히어로 / OG / 404 / 빈 상태 에만. (D1의 "따뜻함 허용 표면"에 한정)
  - **플랫 마크**(favicon·인라인·배지) = 얼굴 생략 시 남는 실루엣. **현 시안은 갓+둥근바디 blob(스템 없음) → 16px에서 도토리/밤과 혼동**. 파비콘용은 스템 힌트 추가 or 갓 오버행 강조 or 볼드 2톤 마크로 실루엣 명확화 필요.
- **00버섯 변형 시스템**: 매력적이나 **MVP는 캐논 1개로 고정**(자산비용·인지도 분산 방지). 변형은 후속 놀이 레이어. 만약 도입 시, 뿔·독·좀비버섯은 실제 넥슨 몬스터명 → IP 표면 증가하므로 얼굴 주도 오리지널 변형 권장.

### D3 — 로고/워드마크 형태 ✅
**결정: 심볼+워드마크 가로 락업을 프라이머리로.**

- 프라이머리 = `[버섯 마크] 메이트`(마크 좌·워드마크 우) → Nextra 좌상단 헤더에 핵맞음.
- 워드마크 = **Pretendard 헤비 웨이트**(Bold/ExtraBold). 별도 디스플레이 폰트 없음(깔끔·신뢰 베이스·무비용). 액센트색으로 한 요소(점·마크) 틴트 가능(컬러 확정 후).
- 파생: **플랫 버섯 마크 단독** = favicon + OG 코너. **워드마크 단독** = 타이트한 곳.
- 기각: 워드마크 단독(마스코트 자산 낭비) / 심볼 중심(놀이 톤·docs 신뢰감 약화·Nextra 헤더 모양과 충돌).

### D1–D3 요약 = 브랜드 아이덴티티(§3.1) 완결
버섯 마스코트(주황 갓+고유 얼굴) · 깔끔·신뢰 베이스 + 따뜻 액센트 · 가로 락업 로고 · Pretendard 헤비 워드마크.

### D4 — 브랜드 액센트: 2색 시스템 ✅
**결정: 틸(기능) + 버섯 오렌지(브랜드).**

- **틸**(기존 제품 ≈ `#5EC8C8` 계열) = 기능 액센트: 링크·활성 네비·포커스 링·섹션 액센트. 가독·신뢰(D1 베이스).
- **버섯 오렌지**(마스코트 갓 색) = 브랜드 액센트: 마스코트·메인 CTA(봇 초대)·히어로 하이라이트·콜아웃 따뜻함.
- **골드**(★) = 브랜드색 아님. 스크린샷 속 데이터 모티프로만 잔류(3색 난립 방지).
- 근거: D1 자세(신뢰 베이스+따뜻 액센트)를 컬러로 그대로 구현 + 기존 제품 두 색 계승 + 역할 분리(틸=가독 임무·오렌지=주목 임무). 엔버봇이 쿨톤이면 오렌지 따뜻함이 자연 차별.
- 기각: 오렌지 단색(링크 가독 약·경고색 충돌) / 틸 단색(마스코트색·사이트색 단절).
- *정확한 hex·틴트 스텝은 다크/라이트 팔레트(§3.7)에서 확정.*

### D5 — 문서화 기준 상태 & 권한/배지 taxonomy 재정의 ✅
**결정: 웹사이트는 post-#36(출시 목표 상태)를 문서화.** + **권한 배지 → 전제조건(온보딩 funnel) taxonomy로 교체.**

- **코드 검증 결과(2026-07-01 main)**: 🛡 `manage_guild` 가 아직 경험치알림([leaderboard/commands.py:88](maple_mate/leaderboard/commands.py#L88))·썬데이·공지알림([notification/commands.py:30](maple_mate/notification/commands.py#L30))을 게이팅. **그러나** ADR-0017/PR #36(구현완료·머지대기, [[notification-unification-decisions]])이 **권한 전부 제거 + 알림 4종 켜기/끄기 통일 + 개인 DM 구독 + 비틱 숨김**을 이미 확정 → 구 `{🔓스펙류/📜이력류/🛡관리권한}` 배지는 obsolete-by-decision.
- **웹은 post-#36 기준**(런칭 아티팩트라 곧 바뀔 상태를 서술하면 즉시 stale). ⚠️ **사이트 배포는 #36 배포와 조율**(#36 안 나간 상태로 사이트 공개 금지 — 안산 기능 서술 방지).
- **새 배지 taxonomy = 전제조건 3티어**(시작하기 page의 온보딩 funnel과 일치):

  | 티어 | 명령 | 아이콘(잠정) |
  |---|---|---|
  | **등록 없이 바로** | /가이드 · /경험치알림 /썬데이알림 /공지알림(권한제거→누구나) | 🔓 |
  | **캐릭터 등록하면** | /스펙 /아이템 /유니온 · /경험치 · /대표지정 /캐릭터목록 | 📝 |
  | **API 키 등록하면** | /스타포스 /잠재 · /스케줄러 | 🔑 |

  - 배지 의미 = "필요 조건"(카테고리 아님). 알림은 하드 전제조건 0 → 정직하게 "등록 없이". **비틱은 목록에서 제외**(숨김).
  - 🔑(key)가 📜(scroll)보다 "API 키 필요"를 직관적으로 전달.
- *배지 색 매핑은 아래 확정.*

### D6 — 배지 색 & 중립 팔레트 ✅
**결정: 🔓 green · 📝 indigo · 🔑 amber-gold. 중립 = 쿨 슬레이트.**

- 🔓 등록없이 = **green**(자유·개방) · 📝 캐릭터 = **indigo**(정체성·등록됨) · 🔑 API키 = **amber-gold**(열쇠·해금).
- 티어별 의미 직관 + 색상환 분산. amber-gold ↔ 브랜드 오렌지 = **treatment로 분리**(배지 = 무톤 틴트 pill + 다크 텍스트 / CTA = 채도 높은 솔리드 버튼). gold는 옐로우쪽으로 lean.
- **중립 그레이 = 쿨 슬레이트**(Nextra 친화). 근거: D1 = 신뢰 베이스 + 따뜻함은 액센트만 → 베이스 중립을 쿨-테크니컬로 두고 오렌지가 따뜻함 전담. 웜그레이는 base까지 따뜻해져 D1과 어긋남.
- *정확한 hex(액센트·배지·중립 스텝)는 다크/라이트 팔레트(§3.7)에서 값 확정.*

### D1–D6 요약 = 컬러 시스템(§3.2) 완결
2색 액센트(틸 기능 + 오렌지 브랜드) · 배지 green/indigo/amber-gold · 쿨 슬레이트 중립 · 골드=데이터 모티프만. (hex는 §3.7)

### D7 — 타이포그래피(§3.3) ✅
**결정: 인라인 명령 = Pretendard 명령 칩(모노 아님). 진짜 코드블록만 JetBrains Mono.**

- **명령 칩**: 인라인 `/명령`은 둥근·액센트 틴트 Pretendard pill → 디스코드 슬래시 UI 멘탈모델 그대로, 한글 완벽 가독, 추가 폰트 0. (사이트 핵심 반복 콘텐츠라 이 결정이 큼)
- **모노**: 실제 코드블록(API 키 문자열·JSON·env = ASCII)에만 **JetBrains Mono**(or Nextra 기본 모노 스택). Latin 모노+한글 폰트 혼재/CJK 모노 로드 회피.
- **패키지(표준·추천 기본, 재검토 가능)**: Pretendard **400/500/700** (+800 워드마크/히어로) · 본문 **line-height ≈1.7**(한글은 Latin 1.5보다 넉넉히) · 헤딩 모듈러 스케일 ≈1.25 비율.

### D8 — 랜딩 히어로(§3.4) ✅
**결정: 스플릿 히어로.**

- **좌**: 워드마크 락업 + 축약 소개문 + **primary CTA(봇 초대 · 오렌지 솔리드)** + secondary(5분 시작 · ghost/text).
- **우**: 히어로 스샷 1개(**경험치 리더보드 그래프** — "우리끼리 순위"가 한눈에) + **버섯 작은 하이라이트**(따뜻함, 종속).
- **스크롤 아래**: 3기둥 카드(비교·비서·함께, 각 소형 스샷) → 5분 시작 티저 → docs.
- CTA 위계 = 오렌지 솔리드(초대) > ghost(5분 시작). 히어로 미디어 = **정적 스샷**(움짤은 후속; 미디어 제약 "재캡처 스크린샷"과 정합).
- 기각: 마스코트 중심(제품 증거 지연·D1 긴장) / 스샷 풀블리드(docs-중립과 충돌·가독 리스크).
- **후속**: 프레임 스타일(§3.6) 확정 후 `designer`로 히어로 목업 2–3안 생성.
- **✅ 히어로 컨셉 확정 = 안 3 "따뜻 강조"**(`docs/website-mockups/hero-3.html`): 오렌지 warm wash 전체 밴드(라이트 `#FFF5EC`/다크 `#1C1008`) + 큰 버섯(120px) 우측 존재감 + 오렌지 구분선·톤 tagline + 카드 상단 컬러 스트라이프. 다크모드 포함 비교 후 선택. **세부 UI/배치는 refine 대상**(§4 리파인 로그 참조).

### D9 — 명령어 페이지 컴포넌트(§3.5) ✅
**결정: 단일 명령어 페이지 + 우측 TOC · 6 feature 그룹 섹션 · 명령당 카드+전제조건 배지.**

- **조직 원리 = feature 그룹**(가이드 미러: 등록·관리 / 스펙·장비 / 이력 / 리더보드 / 스케줄러 숙제 / 알림설정 · **비틱 제외**), **전제조건은 per-명령 배지**(🔓/📝/🔑)로. tier별 섹션 아님(기능이 유저 멘탈모델).
- **페이지 구조 = 단일 페이지 + Nextra 우측 앵커 TOC**. 린 MVP·한 스크롤 스캔·앵커 딥링크·가이드 단일임베드 철학 일치.
- **명령 카드 anatomy(반복 유닛, 린)**: `[명령 칩 제목] [배지]` → 1줄 설명 → 스크린샷(프레임) → optional 짧은 예시/팁. **인자 표 없음**(Discord `/` UI가 이미 노출 — source-of-truth 결정).

### D10 — 스크린샷 프레임(§3.6) ✅
**결정: 틴트 backdrop 프레임(테마 인식). 디바이스/크롬 목업 없음, 더블보더 없음.**

- 스샷 = 네이티브 다크 라운드 엣지 유지 + **소프트 드롭 그림자** + **살짝 브랜드 틴트 패널**(faint 오렌지/틸 wash) 패딩 위에. 캡션 = 하단 뮤트 소형.
- **테마 인식**: 라이트 = 틴트-라이트 backdrop로 다크 스샷 분리 / 다크 = 살짝 엘리베이트 패널 + 헤어라인 보더(다크 스샷이 페이지에 안 묻히게).
- 근거: 스샷이 이미 다크 라운드 카드 → 이중 카드 네스팅 회피. 일관·경량·통제된 브랜드 온기(프레임=정당한 브랜드 표면).
- 기각: 디스코드/브라우저 크롬 목업(무겁·템플릿틱·노후화) / 로우(라이트면 충돌).

### D11 — 다크/라이트 + 반응형(§3.7) ✅
**결정: 기본 = 시스템 설정 따름(Nextra 기본) + 수동 토글. 두 테마 1급. 브랜드-정본(OG·첫페인트·마케팅) = 라이트.**
