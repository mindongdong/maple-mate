> 디스코드 봇이 처음 쓰는 사람에게 어렵다는 실사용자 피드백에서 출발한 작업.
> [sang-se.com](https://www.sang-se.com/interactive-tutorial?entry=landing)의 인터랙티브 튜토리얼
> (풀스크린 + 상단 프로그래스바 + 스텝별 영상/스샷 강조 + 이전/다음)을 레퍼런스로,
> **웹에서 봇 사용법을 한 번 영상처럼 따라가 보는** `/tutorial` 페이지를 만든다.
> grill 세션(2026-07-04)에서 모든 갈림길을 결정 완료했다.
>
> **먼저 읽을 것:** 이 문서 → [website-handoff.md](./website-handoff.md)(site/ 구조·함정·배포).

## 0. 요약

- **무엇을:** `site/`에 풀스크린 인터랙티브 튜토리얼 `/tutorial` 신설. 랜딩 주 CTA를 튜토리얼로 교체.
- **콘텐츠 철학:** 기능 나열이 아니라 **실행 조건·실행 결과물 중심의 사용 시나리오**.
  기능은 계속 늘고 바뀌지만 "명령어를 쓰는 기조"는 안 바뀐다 → 기조를 가르친다.
- **미디어:** CSS 애니메이션 + **운영자가 직접 녹화한 화면 영상**(PC 디스코드 다크 통일).
- **순서:** PR1 = 전체 구현(영상 자리는 스샷+CSS 폴백으로 그 자체 완결) + 촬영 샷리스트 산출
  → 운영자 촬영 → PR2 = mp4 교체만.
- **as-built (2026-07-04, PR1 구현 완료):** `/tutorial` 12스크린·CTA 교체·드리프트 가드
  확장 전부 §4 설계대로. §6 검증 전 항목 통과(빌드·드리프트·pytest 799·라이트/다크/모바일
  스샷·CDP 클릭/키보드/딥링크/클램프 순회 9항목). 촬영 파일명은 §5 표에 확정.

## 1. 배경 — 사용자 요청 원문 요지

- 직접 사용자를 대면해 보니 처음 쓰는 사람에게 봇이 생각보다 어렵다.
- 요즘 유저는 텍스트를 안 읽고 영상·이미지로 확인하고 싶어 한다.
- 레퍼런스처럼 순차 애니메이션 + 프로그래스바 + 영상으로, 끝까지 따라가면
  **서비스 사용법을 영상으로 한 번 본 효과**가 나게 한다.
- 반드시 담을 것(사용자 지정): ① 캐릭터 등록만 하면 되는 기능 vs API 키 등록해야 되는 기능 구분
  ② 캐릭터 등록 방법 ③ API 키 등록 방법 ④ 대상 지정 명령은 대상 안 적으면 **등록한 유저(나) 기준**으로 자동 실행
  ⑤ 어떤 결과가 본인에게만 보이고(ephemeral) 어떤 게 다같이 보이는지.

### 3.1 공개/비공개 정본 매핑 (코드 확인 2026-07-04)

"열리는 문" 스크린(6·9)과 총정리 스크린(11)이 쓰는 단일 소스. 봇 코드의 ephemeral 사용 실태 기준.

| 명령 | 노출 | 근거 |
|---|---|---|
| /스펙 · /아이템 · /유니온 · /스타포스 · /잠재 | **서버에 공개** | 해당 commands.py에 ephemeral 없음 (비교가 목적) |
| /경험치 | **서버에 공개** | 결과 공개, 게이트/에러 안내만 ephemeral (`leaderboard/commands.py`) |
| /내캐릭터 | **서버에 공개** | 공개 defer, 에러만 ephemeral (`mychar/commands.py`, ADR-0018 공개 결정) |
| /스케줄러 | **본인만** | 캐릭터당 ephemeral 메시지 (`scheduler/commands.py`) + DM 구독은 별도 |
| /캐릭터등록 · /키등록 · /캐릭터목록 · /대표지정 | **본인만** | `registration/commands.py` 전부 ephemeral |

- 튜토리얼 카피 라벨은 두 값만: **"다같이 봐요"**(공개) / **"나만 봐요"**(본인만). 사이트 기존 배지 톤과 충돌하지 않게 배지가 아닌 텍스트 라벨로.

## 4. 구현 설계 (PR1)

### 새 파일
- `site/app/tutorial/page.tsx` — 클라이언트 컴포넌트. 풀스크린 오버레이 레이아웃(자체 페이지로 두되 문서 크롬 없이 렌더), 스텝 상태는 `?step=N` (useSearchParams + router.replace), 키보드 ←→, X 버튼 → `/`.
- `site/app/tutorial.css` — 프로그래스바·스텝 전환 페이드·CSS 애니. 기존 토큰(teal/orange, 다크·라이트) 준수.
- `site/data/tutorial-steps.tsx` — 스크린 12~13개의 단일 소스 배열:
  `{ chapter, title, media: {type: 'video'|'image'|'anim', src, poster?, fallback?}, commands: {name: string, visibility?: 'public'|'private'}[] }`.
  `commands.name`은 드리프트 가드용(§6), `visibility`는 "열리는 문"·총정리 스크린의 공개/본인만 라벨 렌더용(§3.1 표가 정본).
- `site/public/tutorial/` — PR2에서 mp4 5개 + poster가 들어갈 자리. PR1은 비움(폴백 스샷은 기존 `shots/` 사용).

### 수정 파일
- `components/Hero.tsx`(또는 Landing) — 주 CTA를 `/tutorial`로 교체(카피 예: "5분 만에 시작하기"), 초대 링크는 보조 버튼으로.
- `content/getting-started.mdx` — 상단에 "영상으로 따라하는 버전 → /tutorial" 배너 한 줄.
- `scripts/check-command-drift.mjs` + `tests/test_website_command_drift.py` — `tutorial-steps.tsx`의 `commands`를 `data/commands.json`과 대조하도록 확장.

### 영상 재생 규격
- mp4(H.264) 무음, `autoPlay muted loop playsInline preload="metadata"` + poster. 클립당 10~30초, 1080p, 목표 2~4MB.
- `prefers-reduced-motion` 시 자동재생 끄고 poster 표시.

## 5. 촬영 샷리스트 (운영자 수작업 → PR2)

공통: PC 디스코드 **다크 테마**, 화면 배율 100%, 무음, 더미/테스트 환경에서 촬영.
**개인정보 주의:** 이메일·타 서버 목록·API 키 실값이 프레임에 들어가면 안 됨(더미 계정 권장, 키는 붙여넣기 직후 화면 전환).

파일은 `site/public/tutorial/` 에 아래 이름으로 넣고, `site/data/tutorial-steps.tsx` 의
해당 스텝 `media.src`/`poster` 만 채우면 끝(각 스텝에 주석으로 경로 명시됨). poster 는
영상 첫 프레임 PNG(`<이름>-poster.png`).
